# 06 — LESSONS (append-only: mistakes, measured surprises, things that cost time)

- LS-01 (2026-10-12) I told the operator Ars Umbris was "macOS-only, cannot run". The README said "tested on macOS only, Linux may work". Do not turn "untested" into "impossible"; try it.
- LS-02 (2026-11-25) I told the operator past option boards / analyst notes are "no longer online". Wrong: investinglive keeps every dated FX-option-expiry post for 2026. Check before asserting something does not exist.
- LS-03 (earlier sessions) My OHLC-only lab forecaster scored below "always range" and my E1 reconstruction showed no edge vs shifted baselines. Cause: zones chosen by proximity, no zone state, no external pillars. Do not repeat proximity-only zone selection.
- LS-04 The previous agents were rejected for: script-graded "passes" with a chart that did not react; caps to hide 33-57 junk zones (R-37); hardcoded per-week values; relabelling instead of root-causing. Any of these = failure.
- LS-05 Pinebox on a root container: needs iproute2 (`ss`), x11-utils (`xdpyinfo`), Chromium `--no-sandbox` wrapper. `pinebox up` refuses by name; read the token, fix the cause.
- LS-06 The ECC GateGuard hook denies the first write to a new directory's first file and the first Bash call; siblings pass afterwards. Present the facts once, retry.
- LS-07 `update_environment` rejects the whole call if one host is unacceptable (web.archive.org / tradingview / bare apex duplicates were in the rejected set). Send a minimal exact list.
- LS-08 (2026-11-25) Eight parallel high-effort reader agents hit the 5-hour usage limit and four died with nothing written. Run <= 2-3 agents at once, narrow scope, and have each write its file incrementally (partial file first) so a kill leaves something.
- LS-09 vela-pinets: `x[1]` inside an `if`/function-local block returns x[0]. Read history ONLY at global scope into named series (close1 = close[1]) and use those. The anchor assert caught this; keep the assert forever.
- LS-10 First Write to a brand-new file path costs a full resend when the gate denies it: first-touch new files with a one-line placeholder, then write the real content.
- LS-11 Pine `for i = a to b` counts DOWN when a > b. Guard every loop whose bounds can cross.
- LS-12 THE PINE IDE TAB RUNS THE SCRIPT ON ONLY THE NEWEST 400 BARS (pine-ide.mjs cfg.limit = 400; station /run trims). A history-dependent engine therefore renders a DIFFERENT (history-starved) forecast in the IDE tab than in the Backtest tab, which feeds every bar up to the replay cursor.
  Fix used: after loading, call the page's own `PlutusPineShell.loadBars({pair, timeframe, limit: 20000})` then `run()` so the IDE runs on its full bar set (1H: newest 5000; 4H: all 2832). Never judge E1/E2/E3 from an IDE frame taken at the default limit.
- LS-13 Backtest tab: every NEW session re-adds whatever scripts were last on a chart (V1 included). V1 needs 80-125 s on 8.7-10.9k bars and the station is single-threaded with a 90 s client timeout -> everything queued behind V1 silently never paints (handle title stays "Indicator"). Remove V1 first, wait for the station to go idle, then add the script.
- LS-14 The IDE inputs panel (legend gear) lists only inputs declared UNTYPED at line start (`i_x = input.int(...)`) under a section marker comment `// ═══ NAME ═══`; it applies a change by rewriting the default in the editor source and re-running. The Backtest chart has the standard Vela settings dialog instead.
- LS-15 ROOT CAUSE of "script on Backtest chart never paints": page console shows `[vela] indicator failed: http://127.0.0.1:9741/prepare - no answer in 90s`. Every script in the room's store (`~/.local/share/pinebox/store/room-0.indicators.json`, API `PUT/DELETE http://127.0.0.1:9443/indicators {name[,script]}`) is auto-added to each session's chart; V1 (81-125 s per run) starves the single-threaded station and the page retries forever.
  Fix: `curl -X DELETE -H 'content-type: application/json' -d '{"name":"Plutus Vision v1"}' http://127.0.0.1:9443/indicators`, then `pinebox down/up`. Debug aid: `node tools/cdp-console.mjs 30` prints the page's console errors. The handle title in the orchestrator is always "Indicator" - not a failure signal.
- LS-16 `fill` is a Pine builtin: a local array named `fill` breaks at run time ("fill.push is not a function"). Avoid builtin names for variables.
- LS-17 Golden week proof that option walls drive the map: EUR/USD 1.14 (2.2bn live) -> DXY 101.14 = Mon/Tue high to the pip; 1.15 (2.4bn live) -> 100.64 = Fri low; Friday's expired 1.137 cluster (2.7bn ghost) -> 101.29 = Wed high. Never judge E1 without the week's option data.
- LS-18 A zone that contains/abuts the anchor price (equilibrium, or a wall the market is sitting on) behaves as a PIVOT that price crosses repeatedly, whatever its confluence. Two tier-1 walls at 101.65/101.66 gave "EXTREME 7% ZFP" and the week chopped through it. ZFP must not be a "will hold" claim for the zone price is inside/adjacent to at the anchor; outer zones (first untested ones above/below) are where reactions are clean. Fix candidate: equilibrium rule = any zone within 0.15 of spot is the pivot (label Equilibrium, ZFP not below the Soft Wall range), and option walls within 10 pips of each other are one wall (aggregate).
