# SECTION 1: EXECUTIVE SUMMARY

The KronosCandleEngine (KCE) is Plutus v3.4's answer to the single greatest weakness of the Engine 3 trade-setup architecture: it generates setups that are spatially correct but temporally blind. Engine 1 maps liquidity zones with 9-pillar confluence scoring. Engine 2 predicts the macro shape chain day by day — Breakout Surge, Whiplash, Swing Scalps, Reversal. Engine 3 takes those zones and shapes and constructs sniper entries with precise SL and TP placement. What none of these engines do is answer the question that kills trades: what does the literal candlestick path between this entry and this TP actually look like? A setup can have a perfect zone, a perfect shape, a perfect RRR — and still die on a Monday morning wick that grazes the SL before the TP is ever reached. The KronosCandleEngine exists to simulate that path, candle by candle, across four telescoping timeframes, and to compute the probability that TP is hit before SL on each of those paths.

The engine is named for Kronos — the personification of time in Greek mythology — because its core function is temporal forward-mapping. Kronos takes the most recent OHLCV history of a pair, feeds it through a candlestick-generating forecasting model (the Kronos model), and produces 15 discrete fractal paths. Each path is a complete multi-timeframe forecast: an H4 weekly structure, conditioned into H1 daily shapes, conditioned into M30 session detail, conditioned into M15 entry precision. This telescoping architecture mirrors the way real market structure unfolds — the weekly chart sets the macro tone, the daily chart defines the shape, the 30-minute chart reveals session behavior, and the 15-minute chart pinpoints the entry. By telescoping rather than forecasting only one timeframe, KCE captures the fractal nesting that makes FX price action predictable.

The critical design principle is the 70/30 intelligence split. Kronos model intelligence — the raw candlestick forecasting — contributes only 30% of the final path probability. The remaining 70% comes from TTE structural intelligence: zone respect checks, shape morphology matching, knowledge-graph historical pattern matching, DXY cascade consistency, and fortress zone integrity. This split is deliberate and non-negotiable. Kronos was trained on equities and crypto data, not FX. It has a documented mean-reversion bias. Its raw forecasts, taken alone, would misjudge directional momentum on trending FX pairs. The TTE structural layer exists to catch those errors — to veto paths that violate zone architecture, to downweight paths whose candle morphology does not match Engine 2's shape prediction, and to boost paths whose zone interaction pattern has historically produced winning trades. The 70/30 split ensures that structural reality always dominates model speculation.

Operationally, KCE runs as four concurrent per-pair instances, one each for DXY, EUR/USD, GBP/USD, and AUD/USD. Each instance is a dedicated GPU process listening on its own port (7091-7094). The DXY instance runs first — mirroring the F2 DXY Primacy module — because DXY direction cascades into the three FX pairs via the established correlation. Each instance generates 15 fractal paths, each containing 4 telescoping layers. At 15 paths per pair, 4 layers per path, and a roughly 0.5-second inference per layer, each pair requires approximately 30 seconds of GPU compute. The four pairs run in parallel across four GPU instances, yielding a total wall-clock time of approximately 90 seconds for the complete KCE pass. The four instances consume approximately 2.7 GB of VRAM (680 MB per instance), well within the 8 GB budget of the target GPU.

The engine delivers three outputs to the downstream pipeline. First, per-setup first-passage probabilities: P(entry triggered), P(TP before SL), P(SL before TP), and expected timing. Second, per-path structural scores that combine zone respect, shape match, and knowledge-graph match into a single 0-1 confidence. Third, advisory confluence metadata that feeds into the existing model_confluence bucket at Step 7.7 without ever removing a structurally-valid setup from the report. KCE is advisory by design — it refines confidence, it does not gate. The only hard gate it enforces is OHLCV sanity: forecasted candles that violate basic price constraints (high less than open, negative volume) are rejected at generation time, not passed downstream. Everything else — zone violations, shape mismatches, low structural scores — produces confidence adjustments, not setup removals. This preserves the proven v3.3 pipeline while adding a forward-looking intelligence layer that was previously absent.

# SECTION 2: ARCHITECTURE

## 2.1 The Telescoping Principle

The KronosCandleEngine uses a four-layer telescoping architecture. Each layer forecasts candles at a specific timeframe, and each layer's forecast conditions the next layer down. The hierarchy flows from the slowest timeframe (H4, which sets the weekly macro structure) to the fastest (M15, which pinpoints entry precision). Information flows downward only — H4 conditions H1, H1 conditions M30, M30 conditions M15. There is no feedback loop. This is intentional: telescoping mirrors how market structure actually propagates. The weekly chart constrains what the daily chart can do; the daily chart constrains what the session chart can do; the session chart constrains what the entry-timeframe chart can do.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     KCE TELESCOPING ARCHITECTURE                             │
│                                                                             │
│  Layer 1: H4 (Weekly Structure)          "Where does the week want to go?"  │
│     Input:  30 H4 bars (≈1 week history) + priorWeekTerminalShape           │
│     Output: 30 forecasted H4 OHLCV bars (Mon 00:00 → Fri close = full week) │
│     Role:   Sets macro direction, range bounds, dominant shape              │
│         │                                                                   │
│         │  convertH4ToH1Anchors()                                          │
│         ▼                                                                   │
│  Layer 2: H1 (Daily Shapes)              "What shape plays out each day?"   │
│     Input:  H4 forecast + 120 H1 bars history                               │
│     Output: 120 H1 OHLCV bars (4 per H4 window, 24 per day, Mon-Fri)        │
│     Role:   Resolves BS/WL/SS morphology within H4 constraints              │
│         │                                                                   │
│         │  H1 range → M30 session window                                    │
│         ▼                                                                   │
│  Layer 3: M30 (Session Detail)           "What happens in each session?"    │
│     Input:  H1 forecast + setupSession window                               │
│     Output: Session-specific M30 bars — only sessions where setups exist:    │
│             London Open 02:00-05:00 = 6 bars | L/NY Ovl 08:00-10:00 = 4     │
│             NY Open 08:30-10:00 = 3 bars     | NY Mid 10:00-14:00 = 8       │
│     Role:   Session-specific only — London/NY where setups exist            │
│         │                                                                   │
│         │  M30 → M15 entry precision                                        │
│         ▼                                                                   │
│  Layer 4: M15 (Entry Precision)          "When exactly does entry trigger?" │
│     Input:  M30 forecast + setupEntry zone edge                             │
│     Output: Session-specific M15 bars — same sessions, 2× granularity:       │
│             London Open = 12 bars | L/NY Ovl = 8 | NY Open = 6 | NY Mid = 16│
│     Role:   Entry precision for active setup sessions only                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2.4 The 70/30 Scoring Pipeline

Every fractal path passes through two scoring stages. The first stage — Kronos generation — produces a raw model confidence reflecting how strongly the model believes this path is likely given the input candlestick patterns. The second stage — TTE structural validation — produces a structural score reflecting how well the path aligns with zone architecture, shape predictions, and historical winning-trade patterns.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    70/30 SCORING PIPELINE                                    │
│                                                                             │
│  STAGE 1 — KRONOS GENERATION (30% weight)                                   │
│  ┌───────────────────────────────────────────────────────────────┐          │
│  │  Input: 30 H4 bars + priorWeekShape                            │          │
│  │  Model: kronos-ohlcv-v2 — generates OHLCV candle forecasts     │          │
│  │  Output: 15 fractal paths, each with modelConfidence 0-1       │          │
│  │         modelConfidence = mean layer probability from ensemble  │          │
│  └──────────────────────────┬────────────────────────────────────┘          │
│                             │                                               │
│                             ▼                                               │
│  STAGE 2 — TTE STRUCTURAL VALIDATION (70% weight)                           │
│  ┌───────────────────────────────────────────────────────────────┐          │
│  │  Rule 1: Zone Respect       (weight 0.40 within stage 2)      │          │
│  │  Rule 2: Shape Morphology   (weight 0.30 within stage 2)      │          │
│  │  Rule 3: Knowledge Graph    (weight 0.30 within stage 2)      │          │
│  │  Rule 4: DXY Cascade        (binary gate — direction override) │          │
│  │  Rule 5: Fortress Integrity (penalty multiplier)               │          │
│  │  Rule 6: OHLCV Sanity       (hard reject — invalid candles)    │          │
│  │  Rule 7: Temporal Consist.  (hard reject — bad timestamps)     │          │
│  │  Output: structuralScore 0-1                                  │          │
│  └──────────────────────────┬────────────────────────────────────┘          │
│                             │                                               │
│                             ▼                                               │
│  FINAL: pathProbability = 0.30 × modelConfidence + 0.70 × structuralScore   │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2.5 DXY-First Ordering

The DXY instance processes first and its directional forecast is injected as a conditioning prior into all three FX pair instances. This mirrors the F2 DXY Primacy module in `src/brains/dxy-primacy.ts`. The cascade matrix is:

| DXY Forecast | EUR/USD Bias | GBP/USD Bias | AUD/USD Bias |
|--------------|-------------|-------------|-------------|
| DXY DOWN (bearish dollar) | LONG bias | LONG bias | LONG bias |
| DXY UP (bullish dollar) | SHORT bias | SHORT bias | SHORT bias |
| DXY NEUTRAL | No conditioning | No conditioning | No conditioning |

The cascade is encoded as a directional prior that adjusts the Kronos model's sampling distribution. It does not hard-force direction — if structural zones strongly contradict the DXY cascade, the path's DXY cascade check (Defense Rule 4) will flag it and apply a structural penalty. The cascade prior influences path generation; the cascade check validates path output. Both must agree for a path to receive full structural score.

## 3.2 CandleScenario — One OHLCV Candle Forecast

```typescript
/**
 * One forecasted OHLCV candle with derived metadata.
 *
 * This is the atomic unit of Kronos output. A FractalPath is composed of
 * arrays of CandleScenario objects at each telescope layer.
 *
 * OHLCV invariants (enforced by OHLCV Sanity check, Defense Rule 6):
 *   - high >= max(open, close)
 *   - low  <= min(open, close)
 *   - volume >= 0
 *   - open, high, low, close are all finite numbers (no NaN, no Infinity)
 */
export interface CandleScenario {
  /** Unix timestamp (ms) marking the candle OPEN time. */
  readonly timestamp: number;
  /** Opening price of the candle. Must be finite. */
  readonly open: number;
  /** Highest price during the candle. Must satisfy high >= max(open, close). */
  readonly high: number;
  /** Lowest price during the candle. Must satisfy low <= min(open, close). */
  readonly low: number;
  /** Closing price of the candle. Must be finite. */
  readonly close: number;
  /** Forecasted relative volume (0-100 scale, normalized to context mean). */
  readonly volume: number;
  /** Model-assigned probability that this candle is the modal forecast (0-1). */
  readonly density: number;
  /** Directional bias of this candle: true if close > open (bullish). */
  readonly isBullish: boolean;
  /** Candle body size as fraction of total range: |close - open| / (high - low). */
  readonly bodyFraction: number;
}
```

## 3.3 RangeAnchor — Parent-Layer Range Constraint

```typescript
/**
 * A range constraint derived from a parent-layer candle.
 *
 * When converting an H4 candle to H1 anchors, the H4 candle's high and low
 * become hard bounds: no H1 candle within that 4-hour window may exceed
 * the H4 high or fall below the H4 low. This is the mathematical basis
 * for telescoping consistency — child timeframes cannot break parent range.
 */
export interface RangeAnchor {
  /** Source timeframe the anchor was derived from. */
  readonly sourceTimeframe: KronosTimeframe;
  /** Source candle index in the parent layer. */
  readonly sourceCandleIndex: number;
  /** Start timestamp of the window this anchor covers (ms). */
  readonly windowStart: number;
  /** End timestamp of the window this anchor covers (ms). */
  readonly windowEnd: number;
  /** Maximum price any child-layer candle may reach within this window. */
  readonly ceilingPrice: number;
  /** Minimum price any child-layer candle may fall to within this window. */
  readonly floorPrice: number;
}
```

## 3.6 FirstPassageResult — Entry/SL/TP Ordering Check

```typescript
/**
 * Result of checking whether TP is reached before SL along a candlestick path.
 *
 * The first-passage problem: given a sequence of OHLCV candles and a trade
 * (entry, SL, TP, direction), determine whether price hits the entry level,
 * then whether TP or SL is touched first after entry.
 *
 * For a LONG trade:
 *   - Entry triggers when a candle LOW <= entry (price falls to entry)
 *   - TP is reached when a candle HIGH >= tp
 *   - SL is hit when a candle LOW <= sl
 *
 * For a SHORT trade:
 *   - Entry triggers when a candle HIGH >= entry (price rises to entry)
 *   - TP is reached when a candle LOW <= tp
 *   - SL is hit when a candle HIGH >= sl
 */
export interface FirstPassageResult {
  /** The setup ID this passage was computed for. */
  readonly setupId: string;
  /** Probability that entry is triggered at all (0-1). */
  readonly pEntryTriggered: number;
  /** Probability that TP is reached before SL, given entry triggered (0-1). */
  readonly pTpBeforeSl: number;
  /** Probability that SL is reached before TP, given entry triggered (0-1). */
  readonly pSlBeforeTp: number;
  /** Probability that neither TP nor SL is reached within the path horizon (0-1). */
  readonly pNeither: number;
  /** Expected number of candles from entry to TP (NaN if TP never reached). */
  readonly expectedBarsToTp: number;
  /** Expected number of candles from entry to SL (NaN if SL never reached). */
  readonly expectedBarsToSl: number;
  /** Expected value in pips: pTp * tpPips - pSl * slPips. */
  readonly expectedValuePips: number;
  /** Quality grade derived from EV and P(TP before SL). */
  readonly qualityGrade: KronosQualityGrade;
  /** Number of paths out of the total that contributed to these statistics. */
  readonly pathsContributing: number;
  /** Total paths generated for this pair. */
  readonly pathsTotal: number;
}
```

## 3.7 StructuralScore — Zone + Shape + Knowledge Graph

```typescript
/**
 * Structural validation score for a single fractal path.
 *
 * Composed of three weighted sub-scores:
 *   - Zone Respect (weight 0.40): does the path bounce at demand floors

 *   - Shape Morphology Match (weight 0.30): does the candle morphology
 *     match Engine 2's predicted shape?
 *   - Knowledge Graph Match (weight 0.30): does this pattern match

 */
export interface StructuralScore {
  /** The path this score applies to. */
  readonly pathId: string;
  /** Zone respect sub-score (0-1). */
  readonly zoneScore: number;
  /** Shape morphology match sub-score (0-1). */
  readonly shapeScore: number;
  /** Knowledge graph historical match sub-score (0-1). */
  readonly knowledgeScore: number;
  /** Combined structural score (0-1) after multiplier and penalty. */
  readonly combined: number;
  /** DXY cascade check result. */
  readonly dxyCascade: DxyCascadeCheck;
  /** Fortress zone integrity penalty multiplier (0.5-1.0, 1.0 = no penalty). */
  readonly fortressMultiplier: number;
  /** Defensive flags raised during scoring. */
  readonly flags: readonly DefenseFlag[];
}
```

# SECTION 4: ENGINE CLASS

## 4.1 Class Overview

The `KronosCandleEngine` class is the primary TypeScript interface to the KCE system. It orchestrates per-pair dispatch, fractal path generation, structural scoring, and first-passage computation. It does NOT contain the Kronos model itself — that lives in a Python inference server (one per pair, on ports 7091-7094). The TypeScript class is the orchestrator and validator; the Python server is the generator.

The class lifecycle is: `initialize()` starts the four Python servers, `generateFractalPath()` is called per pair during Step 7.6, `scorePathStructurally()` validates each path, `computeFirstPassage()` evaluates each setup, and `shutdown()` terminates all servers.

## 4.2 Initialization — Starting Per-Pair Instances

```typescript
  /**
   * Starts the Python inference server for each pair.
   *
   * The DXY instance starts first and must report "healthy" before any
   * FX pair instance starts, because the DXY directional forecast is
   * injected as a cascade prior.
   *
   * @returns true if all instances started successfully, false otherwise.
   *          When false, the engine runs in "structural-only" mode
   *          (no Kronos model — uses Engine 2 shape chain as the sole
   *          forecast source).
   */
  async initialize(): Promise<boolean> {
    this.logger.info('KCE: Initializing per-pair Kronos instances...');

    // Phase 1: Start DXY instance (must succeed for cascade)
    const dxyConfig = this.buildPairConfig('DXY', 0);
    const dxyHandle = await this.startInstance(dxyConfig);
    if (!dxyHandle) {
      this.logger.error('KCE: DXY instance failed to start — structural-only mode');
      return false;
    }
    this.instances.set('DXY', dxyHandle);

    // Phase 2: Start FX pair instances in parallel
    const fxPairs = this.config.pairs.filter((p) => p !== 'DXY');
    const fxResults = await Promise.allSettled(
      fxPairs.map((pair, idx) => {
        const pairConfig = this.buildPairConfig(pair, idx + 1);
        return this.startInstance(pairConfig);
      }),
    );

    let allHealthy = true;
    fxResults.forEach((result, idx) => {
      const pair = fxPairs[idx]!;
      if (result.status === 'fulfilled' && result.value !== null) {
        this.instances.set(pair, result.value);
        this.logger.info(`KCE: ${pair} instance healthy on port ${result.value.port}`);
      } else {
        this.logger.warn(`KCE: ${pair} instance failed — structural-only for this pair`);
        allHealthy = false;
      }
    });

    this.isInitialized = true;
    return allHealthy;
  }

  /**
   * Builds a KronosPairConfig for a specific pair.
   *
   * Adaptive path count: GBP/USD historically has ATR approximately 1.5x
   * EUR/USD, so it gets 75 paths instead of the default 15. This addresses
   * the adversarial challenge of threshold calibration for volatile pairs.
   *
   * @param pair - The trading pair (e.g. 'EUR/USD')
   * @param portOffset - Index into the port range (0 produces 7091, etc.)
   */
  private buildPairConfig(pair: string, portOffset: number): KronosPairConfig {
    const isDxy = pair === 'DXY';
    const pipValue = isDxy ? PIP_VALUE_DXY : PIP_VALUE_FX_4DEC;
    const port = this.config.portBase + portOffset;

    // Adaptive path count: high-volatility pairs get more paths.
    // GBP/USD ATR is ~1.5x EUR/USD per empirical data from v3.2 backtests.
    const basePaths = this.config.pathsPerPair;
    const adaptivePaths = pair === 'GBP/USD'
      ? Math.max(basePaths, this.config.highVolatilityPathBoost)
      : basePaths;

    return {
      pair,
      port,
      modelId: this.config.modelId,
      basePathCount: basePaths,
      adaptivePathCount: adaptivePaths,
      volatilityExpansionFactor: this.config.adaptiveVolatilityFactor,
      contextBars: this.config.contextBars,
      forecastHorizonH4: this.config.forecastHorizonH4,
      pipValue,
      vramBudgetMB: this.config.vramBudgetPerInstanceMB,
      isDxy,
    };
  }

  /**
   * Starts a single Python Kronos inference server via subprocess.
   * Returns a handle if health check passes, null otherwise.
   */
  private async startInstance(config: KronosPairConfig): Promise<KronosInstanceHandle | null> {
    try {
      const childProcess = spawn('python3', [
        '-m', 'plutus.kronos.server',
        '--port', String(config.port),
        '--model', config.modelId,
        '--pair', config.pair,
        '--vram-budget-mb', String(config.vramBudgetMB),
      ], {
        env: {
          ...process.env,
          CUDA_VISIBLE_DEVICES: '0',
          PLUTUS_KRONOS_LOG_LEVEL: 'INFO',
        },
        stdio: ['pipe', 'pipe', 'pipe'],
      });

      const healthy = await this.waitForHealth(config.port, this.config.healthCheckTimeoutMs);
      if (!healthy) {
        childProcess.kill('SIGTERM');
        return null;
      }

      return {
        config,
        port: config.port,
        process: childProcess,
        baseUrl: `http://localhost:${config.port}`,
      };
    } catch (err) {
      this.logger.error(`KCE: Failed to start ${config.pair} instance: ${this.errMsg(err)}`);
      return null;
    }
  }

  /** Polls the health endpoint until the server responds or timeout. */
  private async waitForHealth(port: number, timeoutMs: number): Promise<boolean> {
    const deadline = Date.now() + timeoutMs;
    const url = `http://localhost:${port}/health`;
    while (Date.now() < deadline) {
      try {
        const resp = await fetch(url, { signal: AbortSignal.timeout(2000) });
        if (resp.ok) {
          const body = await resp.json() as KronosHealthResponse;
          if (body.status === 'healthy' && body.model_loaded) {
            return true;
          }
        }
      } catch {
        // Server not ready yet — retry after 500ms
      }
      await this.sleep(500);
    }
    return false;
  }
```

## 4.3 generateFractalPath — Main Entry Point

```typescript
  /**
   * Generates fractal paths for a pair and validates them structurally.
   *
   * This is the primary entry point called by the pipeline at Step 7.6.
   * It dispatches to the per-pair Kronos instance, receives raw candle
   * forecasts, telescopes them across 4 layers, and scores each path.
   *
   * The method returns a PathValidationResult per setup, not per path.
   * First-passage statistics are aggregated across all 15 paths.
   *
   * @param pair - Trading pair (e.g. 'EUR/USD')
   * @param ohlcv - Recent OHLCV bars for the pair (minimum 30 H4 bars)
   * @param zoneMap - Engine 1 zone map snapshot
   * @param shapeChain - Engine 2 shape chain prediction
   * @param priorWeekShape - Previous week's terminal shape classification
   * @param setups - Engine 3 trade setups to evaluate
   * @param dxyForecast - DXY directional forecast (null for DXY pair itself)
   * @returns Array of PathValidationResult, one per setup
   */
  async generateFractalPath(
    pair: string,
    ohlcv: readonly OHLCBar[],
    zoneMap: ZoneMapSnapshot,
    shapeChain: ShapeChain,
    priorWeekShape: ShapeContinuity,
    setups: readonly TradeSetup[],
    dxyForecast: TradeDirection | null,
  ): Promise<readonly PathValidationResult[]> {

    if (!this.isInitialized) {
      throw new KceError('ENGINE_NOT_INITIALIZED',
        'KronosCandleEngine not initialized. Call initialize() first.');
    }

    const handle = this.instances.get(pair);
    if (!handle) {
      this.logger.warn(`KCE: No instance for ${pair} — returning advisory-only results`);
      return setups.map((s) => this.advisoryOnlyResult(s));
    }

    // Validate input data sufficiency
    if (ohlcv.length < this.config.contextBars) {
      this.logger.warn(`KCE: ${pair} has only ${ohlcv.length} bars (need ${this.config.contextBars})`);
      return setups.map((s) => this.advisoryOnlyResult(s));
    }

    if (setups.length === 0) {
      this.logger.info(`KCE: ${pair} has 0 setups — skipping path generation`);
      return [];
    }

    const pathCount = handle.config.adaptivePathCount;

    // ── Phase 1: Request fractal path generation from Kronos model ──
    this.logger.info(`KCE: Generating ${pathCount} fractal paths for ${pair}...`);

    const generationResponse = await this.requestGeneration(
      handle,
      ohlcv,
      priorWeekShape,
      pathCount,
      dxyForecast,
    );

    if (!generationResponse.paths || generationResponse.paths.length === 0) {
      this.logger.error(`KCE: ${pair} returned 0 paths — structural-only fallback`);
      return setups.map((s) => this.advisoryOnlyResult(s));
    }

    // ── Phase 2: Convert raw model output to typed FractalPath objects ──
    const paths: FractalPath[] = [];
    for (let i = 0; i < generationResponse.paths.length; i++) {
      const rawPath = generationResponse.paths[i];
      if (!rawPath) continue;

      const path = await this.assembleFractalPath(rawPath, pair, i, dxyForecast);

      // OHLCV sanity check (Defense Rule 6) — reject invalid paths
      const sanityResult = this.checkOhlcvSanity(path);
      if (!sanityResult.passed) {
        this.logger.warn(`KCE: Path ${i} for ${pair} failed OHLCV sanity: ${sanityResult.reason}`);
        continue;
      }

      paths.push(path);
    }

    if (paths.length === 0) {
      this.logger.error(`KCE: All ${pathCount} paths for ${pair} failed sanity checks`);
      return setups.map((s) => this.advisoryOnlyResult(s));
    }

    this.logger.info(`KCE: ${paths.length}/${pathCount} valid paths for ${pair}`);

    // ── Phase 3: Score each path structurally (the 70% TTE layer) ──
    const scoredPaths: FractalPath[] = [];
    for (const path of paths) {
      const structuralScore = this.scorePathStructurally(
        path,
        zoneMap,
        shapeChain,
        this.knowledgeGraph,
        dxyForecast ?? TradeDirection.NEUTRAL,
        pair,
        handle.config.pipValue,
      );

      const pathProbability =
        this.config.modelWeight * path.modelConfidence +
        this.config.structuralWeight * structuralScore.combined;

      scoredPaths.push({
        ...path,
        structuralScore: structuralScore.combined,
        pathProbability,
        defenseFlags: structuralScore.flags,
      });
    }

    // ── Phase 4: Compute first-passage for each setup ──
    const results: PathValidationResult[] = [];
    for (const setup of setups) {
      const fp = this.computeFirstPassage(scoredPaths, setup, handle.config.pipValue);
      const validation = this.assembleValidationResult(fp, setup, scoredPaths);
      results.push(validation);
    }

    return results;
  }
```

## 4.4 telescopeH4 — Layer 1: H4 Weekly Structure

```typescript
  /**
   * Layer 1 of the telescoping hierarchy: H4 weekly structure forecast.
   *
   * The H4 layer is the root of the telescope. It sets the macro direction,
   * range bounds, and dominant shape for the entire forecast. All lower
   * layers (H1, M30, M15) are conditioned on the H4 output.
   *
   * The Kronos model generates the H4 forecast directly from input context.
   * This method wraps the HTTP call and parses the response into typed
   * CandleScenario objects.
   *
   * @param ohlcv - At least 30 H4 bars of historical context
   * @param priorWeekShape - The terminal shape from the previous week
    * @returns Array of forecasted H4 CandleScenario objects (30 bars)
   */
  async telescopeH4(
    ohlcv: readonly OHLCBar[],
    priorWeekShape: ShapeContinuity,
  ): Promise<readonly CandleScenario[]> {

    if (ohlcv.length < this.config.contextBars) {
      throw new KceError('INSUFFICIENT_CONTEXT',
        `H4 telescope requires ${this.config.contextBars} bars, got ${ohlcv.length}`);
    }

    // Extract the context window (most recent 30 H4 bars)
    const context = ohlcv.slice(-this.config.contextBars);

    // Build the conditioning prompt with prior-week terminal shape
    const requestBody: KronosGenerateRequest = {
      context: context.map((b) => ({
        timestamp: b.timestamp,
        open: b.open,
        high: b.high,
        low: b.low,
        close: b.close,
        volume: b.volume,
      })),
      horizon: this.config.forecastHorizonH4,
      timeframe: KronosTimeframe.H4,
      prior_shape: priorWeekShape.terminalShape,
      prior_energy: priorWeekShape.energyLevel,
      prior_ended_at_extreme: priorWeekShape.endedAtExtreme,
    };

    const resp = await fetch(`${this.baseUrl}/${KronosEndpoint.GENERATE}`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(requestBody),
      signal: AbortSignal.timeout(this.config.maxInferenceMs),
    });

    if (!resp.ok) {
      throw new KceError('GENERATION_FAILED',
        `H4 generation HTTP ${resp.status}: ${await resp.text().catch(() => 'unreadable')}`);
    }

    const data = await resp.json() as KronosGenerateResponse;

    // Parse raw candles into typed CandleScenario objects
    return data.candles.map((c, idx) => this.parseCandle(c, idx, KronosTimeframe.H4));
  }

  /**
   * Parses a raw candle from the model response into a typed CandleScenario.
   *
   * Computes derived fields (isBullish, bodyFraction) and validates
   * basic numeric finiteness. Full OHLCV invariant validation happens
   * in Defense Rule 6 (checkOhlcvSanity).
   */
  private parseCandle(
    raw: KronosRawCandle,
    index: number,
    timeframe: KronosTimeframe,
  ): CandleScenario {
    const open = raw.open;
    const high = raw.high;
    const low = raw.low;
    const close = raw.close;

    // Compute timeframe-appropriate timestamp if not provided
    const msPerBar = TIMEFRAME_MS[timeframe];
    const timestamp = raw.timestamp ?? (Date.now() + index * msPerBar);

    const range = high - low;
    const bodyFraction = range > 0 ? Math.abs(close - open) / range : 0;

    return {
      timestamp,
      open,
      high,
      low,
      close,
      volume: Math.max(0, raw.volume ?? 50),
      density: Math.max(0, Math.min(1, raw.density ?? 0.5)),
      isBullish: close >= open,
      bodyFraction,
    };
  }
```

## 4.5 telescopeH1 — Layer 2: H1 Daily Shapes

```typescript
  /**
   * Layer 2: H1 daily shape forecast conditioned on the H4 weekly structure.
   *
   * Each H4 candle spans a 4-hour window. Within that window, the H4
   * candle's high and low become hard range bounds: no H1 candle may
   * exceed the H4 high or fall below the H4 low. The H1 forecast fills
    * in the intra-window shape (4 H1 bars per H4 bar).
   *
    * @param h4Forecast - The 30 forecasted H4 candles from Layer 1
    * @param ohlcvH1 - At least 120 H1 bars of historical context (1 week)
   * @returns H1 layer with range anchors from the H4 forecast
   */
  async telescopeH1(
    h4Forecast: readonly CandleScenario[],
    ohlcvH1: readonly OHLCBar[],
  ): Promise<TelescopeLayer> {

    if (h4Forecast.length === 0) {
      throw new KceError('EMPTY_H4_FORECAST', 'Cannot telescope H1 from empty H4 forecast');
    }

    if (ohlcvH1.length < 120) {
      throw new KceError('INSUFFICIENT_H1_CONTEXT',
        `H1 telescope requires 120 bars, got ${ohlcvH1.length}`);
    }

    // Step 1: Convert H4 candles to H1 range anchors
    const anchors = this.convertH4ToH1Anchors(h4Forecast);

    // Step 2: Request H1 forecast conditioned on H4 anchors
    const requestBody: KronosTelescopeRequest = {
      timeframe: KronosTimeframe.H1,
      context: ohlcvH1.slice(-120).map((b) => ({
        timestamp: b.timestamp, open: b.open, high: b.high,
        low: b.low, close: b.close, volume: b.volume,
      })),
      parent_anchors: anchors.map((a) => ({
        window_start: a.windowStart,
        window_end: a.windowEnd,
        ceiling: a.ceilingPrice,
        floor: a.floorPrice,
      })),
      bars_per_anchor: BARS_PER_H4_WINDOW,
    };

    const resp = await fetch(`${this.baseUrl}/${KronosEndpoint.TELESCOPE}`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(requestBody),
      signal: AbortSignal.timeout(this.config.maxInferenceMs),
    });

    if (!resp.ok) {
      throw new KceError('TELESCOPE_H1_FAILED', `H1 telescope HTTP ${resp.status}`);
    }

    const data = await resp.json() as KronosTelescopeResponse;

    // Step 3: Parse candles and clamp to H4 anchor bounds
    const h1Candles: CandleScenario[] = data.candles.map((c, idx) => {
      const parsed = this.parseCandle(c, idx, KronosTimeframe.H1);
      const anchor = this.findContainingAnchor(parsed.timestamp, anchors);
      return anchor ? this.clampToAnchor(parsed, anchor) : parsed;
    });

    return {
      timeframe: KronosTimeframe.H1,
      candles: h1Candles,
      parentLayer: KronosTimeframe.H4,
      rangeAnchors: anchors,
      isConditioned: true,
      layerConfidence: data.confidence ?? 0.5,
    };
  }

  /**
   * Clamps a candle's high/low to a range anchor's bounds.
   *
   * If the model produces an H1 candle with a high above the H4 ceiling,
   * we clamp the high to the ceiling and adjust the close if necessary.
   * This enforces telescoping consistency: child timeframes cannot exceed
   * parent timeframe range bounds.
   */
  private clampToAnchor(candle: CandleScenario, anchor: RangeAnchor): CandleScenario {
    const ceiling = anchor.ceilingPrice;
    const floor = anchor.floorPrice;

    const clampedHigh = Math.min(candle.high, ceiling);
    const clampedLow = Math.max(candle.low, floor);
    const clampedOpen = Math.max(floor, Math.min(ceiling, candle.open));
    const clampedClose = Math.max(floor, Math.min(ceiling, candle.close));

    const range = clampedHigh - clampedLow;
    const bodyFraction = range > 0 ? Math.abs(clampedClose - clampedOpen) / range : 0;

    return {
      timestamp: candle.timestamp,
      open: clampedOpen,
      high: clampedHigh,
      low: clampedLow,
      close: clampedClose,
      volume: candle.volume,
      density: candle.density,
      isBullish: clampedClose >= clampedOpen,
      bodyFraction,
    };
  }

  /** Finds the range anchor that contains a given timestamp. */
  private findContainingAnchor(
    timestamp: number,
    anchors: readonly RangeAnchor[],
  ): RangeAnchor | null {
    for (const anchor of anchors) {
      if (timestamp >= anchor.windowStart && timestamp < anchor.windowEnd) {
        return anchor;
      }
    }
    return null;
  }
```

## 4.7 convertH4ToH1Anchors — Anchor Conversion

```typescript
  /**
   * Converts H4 forecast candles into H1 range anchors.
   *
   * Each H4 candle covers a 4-hour window (e.g. Monday 00:00-04:00).

      anchors.push({
        sourceTimeframe: KronosTimeframe.H4,
        sourceCandleIndex: i,
        windowStart: h4.timestamp,
        windowEnd: h4.timestamp + MS_PER_H4_BAR,
        ceilingPrice: h4.high,
        floorPrice: h4.low,
      });
    }

    return anchors;
```

## 4.8 scorePathStructurally — The 70% TTE Validation

```typescript
  /**
   * Scores a fractal path against TTE structural intelligence.
   *
   * This is the heart of the 70% weighting. The path's candle sequence
   * is checked against zone architecture (Rule 1), shape morphology
   * (Rule 3), knowledge graph (Rule 5), DXY cascade (Rule 4), and
   * fortress zone integrity (Rule 2). The sub-scores are combined
   * using the configured weights.
   *
   * @param path - The fractal path to score
   * @param zoneMap - Engine 1 zone map
   * @param shapeChain - Engine 2 shape chain
   * @param knowledgeGraph - Historical trade patterns
   * @param dxyForecast - DXY direction forecast
   * @param pair - Trading pair
   * @param pipValue - Pip value for the pair
   * @returns StructuralScore with sub-scores, combined score, and flags
   */
  scorePathStructurally(
    path: FractalPath,
    zoneMap: ZoneMapSnapshot,
    shapeChain: ShapeChain,
    knowledgeGraph: readonly KnowledgeNode[],
    dxyForecast: TradeDirection,
    pair: string,
    pipValue: number,
  ): StructuralScore {

    const ctx: DefenseContext = {
      path, zoneMap, shapeChain, knowledgeGraph, dxyForecast, pair, pipValue,
    };

    const flags: DefenseFlag[] = [];

    // ── Rule 1: Zone Respect (weight 0.40) ──
    const zoneResult = this.checkZoneRespect(ctx);
    if (zoneResult.flags.length > 0) flags.push(...zoneResult.flags);

    // ── Rule 2: Fortress Zone Integrity (penalty multiplier) ──
    const fortressResult = this.checkFortressIntegrity(ctx);
    if (fortressResult.flags.length > 0) flags.push(...fortressResult.flags);

    // ── Rule 3: Shape Morphology Match (weight 0.30) ──
    const shapeResult = this.checkShapeMorphology(ctx);
    if (shapeResult.flags.length > 0) flags.push(...shapeResult.flags);

    // ── Rule 4: DXY Cascade Consistency (binary check + penalty) ──
    const dxyResult = this.checkDxyCascade(ctx);
    if (dxyResult.flags.length > 0) flags.push(...dxyResult.flags);

    // ── Rule 5: Knowledge Graph Historical Match (weight 0.30) ──
    const knowledgeResult = this.checkKnowledgeGraph(ctx);
    if (knowledgeResult.flags.length > 0) flags.push(...knowledgeResult.flags);

    // ── Rule 7: Temporal Consistency (hard reject if failed) ──
    const temporalResult = this.checkTemporalConsistency(ctx);
    if (!temporalResult.passed) {
      flags.push(...temporalResult.flags);
      return {
        pathId: path.pathId,
        zoneScore: 0, shapeScore: 0, knowledgeScore: 0,
        combined: 0, dxyCascade: dxyResult.check,
        fortressMultiplier: 0, flags,
      };
    }

    // ── Combine sub-scores with configured weights ──
    const w = this.config.structuralWeights;
    const rawCombined =
      w.zone * zoneResult.score +
      w.shape * shapeResult.score +
      w.knowledge * knowledgeResult.score;

    // Apply fortress penalty and DXY cascade penalty
    const combined = Math.max(0, Math.min(1,
      rawCombined * fortressResult.multiplier - dxyResult.check.penalty,
    ));

    return {
      pathId: path.pathId,
      zoneScore: zoneResult.score,
      shapeScore: shapeResult.score,
      knowledgeScore: knowledgeResult.score,
      combined,
      dxyCascade: dxyResult.check,
      fortressMultiplier: fortressResult.multiplier,
      flags,
    };
  }
```

## 4.9 computeFirstPassage — Entry/SL/TP Ordering

```typescript
  /**
   * Computes first-passage probabilities for a setup across all paths.
   *
   * For each path, walks the M15 candle sequence (the finest layer) and
   * determines:
   *   1. Whether entry is triggered (price reaches the entry level)
   *   2. Whether TP or SL is hit first after entry
   *   3. How many candles until TP or SL
   *
   * Results are aggregated across all paths, weighted by pathProbability.
   *
   * @param paths - All scored fractal paths for this pair
   * @param setup - The trade setup to evaluate
   * @param pipValue - Pip value for the pair
   * @returns FirstPassageResult with weighted probabilities
   */
  computeFirstPassage(
    paths: readonly FractalPath[],
    setup: TradeSetup,
    pipValue: number,
  ): FirstPassageResult {
    if (paths.length === 0) {
      throw new KceError('NO_PATHS', 'Cannot compute first-passage with zero paths');
    }

    const isLong = setup.direction === TradeDirection.LONG;
    const entry = setup.entry;
    const sl = setup.sl;
    const tp = setup.tp;

    let triggeredCount = 0;
    let tpFirstCount = 0;
    let slFirstCount = 0;

    let totalBarsToTp = 0;
    let tpPathCount = 0;
    let totalBarsToSl = 0;
    let slPathCount = 0;

    for (const path of paths) {
      const m15Layer = path.layers.find((l) => l.timeframe === KronosTimeframe.M15);
      if (!m15Layer || m15Layer.candles.length === 0) continue;

      let entryTriggered = false;
      let entryBarIndex = -1;

      for (let i = 0; i < m15Layer.candles.length; i++) {
        const candle = m15Layer.candles[i];
        if (!candle) continue;

        if (!entryTriggered) {
          if (isLong && candle.low <= entry) {
            entryTriggered = true;
            entryBarIndex = i;
          } else if (!isLong && candle.high >= entry) {
            entryTriggered = true;
            entryBarIndex = i;
          }
          if (!entryTriggered) continue;
        }

        // Entry is triggered — check TP and SL this bar
        const tpReached = isLong ? candle.high >= tp : candle.low <= tp;
        const slReached = isLong ? candle.low <= sl : candle.high >= sl;

        if (tpReached && slReached) {
          // Same candle hits both — closer level wins
          const tpDist = isLong
            ? Math.abs(candle.high - tp)
            : Math.abs(tp - candle.low);
          const slDist = isLong
            ? Math.abs(sl - candle.low)
            : Math.abs(candle.high - sl);
          if (tpDist <= slDist) {
            tpFirstCount++;
            totalBarsToTp += (i - entryBarIndex);
            tpPathCount++;
          } else {
            slFirstCount++;
            totalBarsToSl += (i - entryBarIndex);
            slPathCount++;
          }
          break;
        } else if (tpReached) {
          tpFirstCount++;
          totalBarsToTp += (i - entryBarIndex);
          tpPathCount++;
          break;
        } else if (slReached) {
          slFirstCount++;
          totalBarsToSl += (i - entryBarIndex);
          slPathCount++;
          break;
        }
      }

      if (entryTriggered) triggeredCount++;
    }

    // Compute probabilities
    const pEntryTriggered = triggeredCount / paths.length;
    const denominator = triggeredCount > 0 ? triggeredCount : 1;
    const pTpBeforeSl = tpFirstCount / denominator;
    const pSlBeforeTp = slFirstCount / denominator;

    const unresolved = triggeredCount - tpFirstCount - slFirstCount;
    const pNeither = unresolved / denominator;

    const expectedBarsToTp = tpPathCount > 0 ? totalBarsToTp / tpPathCount : NaN;
    const expectedBarsToSl = slPathCount > 0 ? totalBarsToSl / slPathCount : NaN;

    const tpPips = Math.abs(tp - entry) / pipValue;
    const slPips = Math.abs(entry - sl) / pipValue;
    const expectedValuePips = pTpBeforeSl * tpPips - pSlBeforeTp * slPips;

    const qualityGrade = this.gradeFirstPassage(expectedValuePips, pTpBeforeSl);

    return {
      setupId: setup.setupId,
      pEntryTriggered, pTpBeforeSl, pSlBeforeTp, pNeither,
      expectedBarsToTp, expectedBarsToSl, expectedValuePips,
      qualityGrade,
      pathsContributing: triggeredCount,
      pathsTotal: paths.length,
    };
  }

  /**
   * Assigns a quality grade based on expected value and win probability.
   *
   * Grade boundaries (aligned with TimesFM grading):
   *   A: EV > 25 pips AND P(TP) > 0.55
   *   B: EV > 8 pips  AND P(TP) > 0.42
   *   C: EV > -8 pips
   *   D: EV > -25 pips
   *   F: EV <= -25 pips
   *
   * Rationale for thresholds:
   *   - 25 pips: meaningful profit for a swing trade (covers spread + commission)
   *   - 8 pips: break-even after typical FX spread (1.5 pips) and commission
   *   - -8 pips: acceptable drawdown tolerance for scalp opportunities
   *   - -25 pips: hard floor; beyond this the setup is structurally unprofitable
   */
  private gradeFirstPassage(evPips: number, pTp: number): KronosQualityGrade {
    if (evPips > 25.0 && pTp > 0.55) return 'A';
    if (evPips > 8.0 && pTp > 0.42) return 'B';
    if (evPips > -8.0) return 'C';
    if (evPips > -25.0) return 'D';
    return 'F';
  }
```

# SECTION 5: DEFENSE RULES

Each defense rule is a structural validation check on Kronos-generated paths. They implement the 70% TTE intelligence layer. Every rule has: a stated purpose, a compilable implementation, a threshold with rationale, an edge-case handler, and a test reference (see Section 7).

## 5.1 Defense Rule 1 — Zone Respect Check

**Purpose:** Verify that the fractal path respects Engine 1's zone architecture. When price approaches a demand zone floor, the path should show a bounce (price reverses upward). When price approaches a supply zone ceiling, the path should show a rejection (price reverses downward). A path that slices through multiple demand zones without bouncing — or rockets through supply zones without rejecting — is structurally suspect. It likely reflects the Kronos model's mean-reversion bias overriding real zone interaction dynamics.

**Threshold:** A path must bounce or reject at 60% or more of zone touches to receive zoneScore above 0.5. At 60% the score is 0.5; at 100% it reaches 1.0. Below 60%, the score drops linearly toward 0. The 60% floor reflects empirical data: in the 43 winning trades, price respected zone edges 78% of the time on average. A path that respects fewer than 60% of zones is worse than the historical baseline.

**Threshold sensitivity:** At +1% (61%), the score increases by approximately 0.025. At -1% (59%), the score drops below 0.5, which reduces the path's structural weight enough to downgrade it from grade B to grade C. This sensitivity is intentional — the zone respect check is the highest-weighted component (0.40) and small changes in it have outsized impact on the final structural score.

**Edge case:** If a path touches zero zones (price stays in a narrow range away from any zone edge), the score defaults to 0.5 (neutral — not penalized, not rewarded). This handles the degenerate case where the forecasted week is a pure consolidation with no zone interaction. Referenced in Test 1 (Section 7).

```typescript
  /**
   * Rule 1: Zone Respect Check.
   *
   * Walks the path's H1 candle sequence and checks each zone touch.
   * A zone touch occurs when a candle's wick reaches a zone edge.
   * The check verifies that price bounces at demand floors and
   * rejects at supply ceilings.
   *
   * @returns Sub-score (0-1) and any defense flags.
   */
  private checkZoneRespect(ctx: DefenseContext): { score: number; flags: DefenseFlag[] } {
    const flags: DefenseFlag[] = [];
    const zones = ctx.zoneMap.zones;
    const candles = this.getLayerCandles(ctx.path, KronosTimeframe.H1);

    if (zones.length === 0 || candles.length === 0) {
      // Edge case: no zones or no candles — neutral score
      return { score: 0.5, flags };
    }

    let touches = 0;
    let respected = 0;

    for (const candle of candles) {
      for (const zone of zones) {
        const isDemand = zone.type === ZoneType.BOM_DEMAND ||
                         zone.type === ZoneType.MOM_DEMAND ||
                         zone.type === ZoneType.LSZ_DEMAND ||
                         zone.type === ZoneType.IP_DEMAND;

        const zoneFloor = zone.floor;
        const zoneCeiling = zone.ceiling;
        const touchTolerance = ctx.pipValue * ZONE_TOUCH_TOLERANCE_PIPS;

        if (isDemand) {
          const touchesFloor = candle.low <= zoneFloor + touchTolerance;
          if (touchesFloor) {
            touches++;
            const bounceSize = candle.close - candle.low;
            if (bounceSize > ctx.pipValue * MIN_BOUNCE_PIPS) {
              respected++;
            } else {
              flags.push({
                ruleId: 1, ruleName: 'Zone Respect', severity: 'WARN',
                message: `Candle at ${new Date(candle.timestamp).toISOString()} touched demand floor ${zoneFloor.toFixed(5)} but did not bounce (close=${candle.close.toFixed(5)}, low=${candle.low.toFixed(5)})`,
              });
            }
          }
        } else {
          const touchesCeiling = candle.high >= zoneCeiling - touchTolerance;
          if (touchesCeiling) {
            touches++;
            const rejectSize = candle.high - candle.close;
            if (rejectSize > ctx.pipValue * MIN_BOUNCE_PIPS) {
              respected++;
            } else {
              flags.push({
                ruleId: 1, ruleName: 'Zone Respect', severity: 'WARN',
                message: `Candle at ${new Date(candle.timestamp).toISOString()} touched supply ceiling ${zoneCeiling.toFixed(5)} but did not reject (close=${candle.close.toFixed(5)}, high=${candle.high.toFixed(5)})`,
              });
            }
          }
        }
      }
    }

    const ratio = touches > 0 ? respected / touches : 0.5;
    const score = touches > 0
      ? Math.max(0, Math.min(1, (ratio - ZONE_RESPECT_FLOOR) / (1 - ZONE_RESPECT_FLOOR)))
      : 0.5;

    return { score, flags };
  }
```

**Constants:**

```typescript

/** How close to a zone edge counts as a touch (pips). */
const ZONE_TOUCH_TOLERANCE_PIPS = 5;
/** Minimum zone-respect ratio for score above 0. */
const ZONE_RESPECT_FLOOR = 0.60;
```

## 5.2 Defense Rule 2 — Fortress Zone Integrity

**Purpose:** FORTRESS zones — those with ZFP of 15 or below — are the strongest structural levels in the system. They have been tested and held multiple times. A path that casually pierces a FORTRESS zone with weak candles (small body, no follow-through) is almost certainly wrong. This rule penalizes such paths. A FORTRESS zone can only be legitimately pierced by a strong candle (bodyFraction above 0.6) accompanied by follow-through in the next bar.

**Rationale for 15% threshold:** The general FORTRESS classification uses ZFP below 20 (see `trading-constants.ts` ZFP_FORTRESS_THRESHOLD = 20). KCE uses a stricter 15 threshold for piercing penalties because the cost of a false fortress-pierce flag is lower than the cost of missing a genuine weak-zone failure. At 15, only the most battle-tested zones receive the fortress penalty protection. At 16 (plus one), the zone is treated as STRONG rather than FORTRESS, and the piercing penalty is halved. At 14 (minus one), nothing changes — the zone is already FORTRESS.

**Edge case:** If a path pierces a FORTRESS zone with a strong candle (bodyFraction above 0.6) AND the next candle continues in the piercing direction, the pierce is considered legitimate. No penalty is applied. This handles genuine breakout scenarios where even the strongest zones fail under sufficient momentum. Referenced in Test 5 (Section 7).

```typescript
  /**
   * Rule 2: Fortress Zone Integrity.
   *
   * Checks whether the path pierces any FORTRESS zone (ZFP <= 15%).
   * Piercing without a strong candle + follow-through triggers a
   * penalty multiplier on the structural score.
   *
   * @returns Penalty multiplier (0.5 if penalized, 1.0 if clean) and flags.
   */
  private checkFortressIntegrity(ctx: DefenseContext): { multiplier: number; flags: DefenseFlag[] } {
    const flags: DefenseFlag[] = [];
    const zones = ctx.zoneMap.zones;
    const candles = this.getLayerCandles(ctx.path, KronosTimeframe.H1);

    const fortressThreshold = this.config.fortressZfpThreshold; // 15
    const piercePenalty = this.config.fortressPiercePenalty;     // 0.5

    let violations = 0;
    let totalFortressZones = 0;

    for (const zone of zones) {
      if (zone.zfp > fortressThreshold) continue;
      totalFortressZones++;

      const isDemand = zone.type === ZoneType.BOM_DEMAND ||
                       zone.type === ZoneType.MOM_DEMAND ||
                       zone.type === ZoneType.LSZ_DEMAND ||
                       zone.type === ZoneType.IP_DEMAND;

      for (let i = 0; i < candles.length; i++) {
        const candle = candles[i];
        if (!candle) continue;

        if (isDemand) {
          const pierced = candle.close < zone.floor;
          if (pierced) {
            const isStrongCandle = candle.bodyFraction > STRONG_CANDLE_BODY_THRESHOLD;
            const nextCandle = candles[i + 1];
            const hasFollowThrough = nextCandle ? nextCandle.close < candle.close : false;
            if (!isStrongCandle || !hasFollowThrough) {
              violations++;
              flags.push({
                ruleId: 2, ruleName: 'Fortress Integrity', severity: 'WARN',
                message: `Path pierces FORTRESS demand zone (floor=${zone.floor.toFixed(5)}, ZFP=${zone.zfp}%) with weak candle (bodyFraction=${candle.bodyFraction.toFixed(2)})`,
              });
            }
          }
        } else {
          const pierced = candle.close > zone.ceiling;
          if (pierced) {
            const isStrongCandle = candle.bodyFraction > STRONG_CANDLE_BODY_THRESHOLD;
            const nextCandle = candles[i + 1];
            const hasFollowThrough = nextCandle ? nextCandle.close > candle.close : false;
            if (!isStrongCandle || !hasFollowThrough) {
              violations++;
              flags.push({
                ruleId: 2, ruleName: 'Fortress Integrity', severity: 'WARN',
                message: `Path pierces FORTRESS supply zone (ceiling=${zone.ceiling.toFixed(5)}, ZFP=${zone.zfp}%) with weak candle (bodyFraction=${candle.bodyFraction.toFixed(2)})`,
              });
            }
          }
        }
      }
    }

    if (totalFortressZones === 0) {
      return { multiplier: 1.0, flags };
    }

    const violationRate = violations / totalFortressZones;
    const multiplier = Math.max(piercePenalty, 1.0 - violationRate * 0.5);

    return { multiplier, flags };
  }
```

## 5.3 Defense Rule 3 — Shape Morphology Match

**Purpose:** Verify that the candle morphology in the fractal path matches Engine 2's predicted shape for the corresponding day. Engine 2 predicts a shape chain — Monday is BS, Tuesday is SS, Wednesday is WL, etc. Each shape has a characteristic candle morphology. A path whose candles look like SS (tight overlap, small bodies) on a day Engine 2 predicted BS (expanding ranges, large bodies) receives a low shape match score.

**Shape morphology table:**

| Shape | Body Size | Directional Close | Typical Pattern |
|-------|-----------|-------------------|-----------------|
| BS (Breakout Surge) | 0.50-1.00 | Either (but consistent within day) | Large bodies, expanding range |
| SS (Swing Scalps) | 0.00-0.35 | Mixed | Small bodies, tight overlap |
| WL (Whiplash) | 0.20-0.60 | Reversal | Moderate body, large wick |
| RWL (Reverse Whiplash) | 0.20-0.60 | Reversal | Moderate body, large wick |
| R (Reversal) | 0.25-0.55 | Clean directional | Moderate body |
| WLS (Wide Range Swing) | 0.30-0.70 | Either | Wide range, directional |
| DWL (Dead Whales) | 0.10-0.40 | Either | Low energy, narrow |
| PBS (Piercing BS) | 0.45-0.90 | Directional | Strong body, pierces zone |
| STORM (SS+delayed WL) | 0.15-0.50 | Mixed then sharp | Volatile |
| PWL (Piercing Whiplash) | 0.25-0.60 | Reversal | Pierces then rejects |
| PRWL (Piercing RWL) | 0.25-0.60 | Reversal | Pierces then rejects |
| RS (Recovery Surge) | 0.40-0.85 | Directional | Sharp recovery |

**Threshold:** Morphology match ratio of 0.7 or above for score above 0.5. The 0.7 threshold means at least 7 of 10 candles in the day must match the expected morphology pattern. Referenced in Test 6 (Section 7).

**Edge case:** If Engine 2 predicts no shape for a given day (null or undefined), the score defaults to 0.5 (neutral). This handles the case where the shape chain is incomplete or the day falls outside the prediction window.

```typescript
  /**
   * Rule 3: Shape Morphology Match.
   *
   * Compares the candle morphology in the path against Engine 2's
   * predicted shape for each day. Uses body fraction and directional
   * close as morphology indicators.
   *
   * @returns Sub-score (0-1) and flags.
   */
  private checkShapeMorphology(ctx: DefenseContext): { score: number; flags: DefenseFlag[] } {
    const flags: DefenseFlag[] = [];
    const shapeChain = ctx.shapeChain;
    const candles = this.getLayerCandles(ctx.path, KronosTimeframe.H1);

    if (candles.length === 0) {
      return { score: 0.5, flags };
    }

    const dayGroups = this.groupCandlesByDay(candles);
    let totalCandles = 0;
    let matchedCandles = 0;

    for (const [dayKey, dayCandles] of dayGroups) {
      const predictedShape = this.getPredictedShapeForDay(shapeChain, dayKey);
      if (!predictedShape) continue; // No prediction — neutral

      const expected = SHAPE_MORPHOLOGY_MAP[predictedShape];
      if (!expected) continue;

      let dayMatched = 0;
      for (const candle of dayCandles) {
        totalCandles++;
        if (this.candleMatchesMorphology(candle, expected)) {
          matchedCandles++;
          dayMatched++;
        }
      }

      const dayRatio = dayCandles.length > 0 ? dayMatched / dayCandles.length : 0;
      if (dayRatio < MORPHOLOGY_MATCH_THRESHOLD) {
        flags.push({
          ruleId: 3, ruleName: 'Shape Morphology', severity: 'WARN',
          message: `Day ${dayKey}: path morphology matches ${predictedShape} only ${(dayRatio * 100).toFixed(0)}% (threshold ${(MORPHOLOGY_MATCH_THRESHOLD * 100).toFixed(0)}%)`,
        });
      }
    }

    const ratio = totalCandles > 0 ? matchedCandles / totalCandles : 0.5;
    const score = totalCandles > 0 ? Math.max(0, Math.min(1, ratio)) : 0.5;

    return { score, flags };
  }

  private candleMatchesMorphology(candle: CandleScenario, expected: ShapeMorphology): boolean {
    const bodyMatch = candle.bodyFraction >= expected.minBody &&
                      candle.bodyFraction <= expected.maxBody;
    const directionMatch = expected.directionalClose === null
      ? true
      : (expected.directionalClose === 'bullish' ? candle.isBullish : !candle.isBullish);
    return bodyMatch && directionMatch;
  }

  private groupCandlesByDay(candles: readonly CandleScenario[]): Map<string, CandleScenario[]> {
    const groups = new Map<string, CandleScenario[]>();
    for (const candle of candles) {
      const dayKey = new Date(candle.timestamp).toISOString().slice(0, 10);
      const existing = groups.get(dayKey) ?? [];
      existing.push(candle);
      groups.set(dayKey, existing);
    }
    return groups;
  }

  private getPredictedShapeForDay(shapeChain: ShapeChain, dayKey: string): ShapeCode | null {
    const dayEntry = shapeChain.dayPredictions?.find(
      (d) => d.day === dayKey || (d.date && d.date.startsWith(dayKey)),
    );
    return dayEntry?.shape ?? shapeChain.currentShape ?? null;
  }
```

## 5.4 Defense Rule 4 — DXY Cascade Consistency

**Purpose:** For FX pairs, the path direction must align with the DXY forecast. The correlation is mechanical: DXY down means dollar weakness, so EUR/USD, GBP/USD, and AUD/USD should be biased LONG. A path that shows EUR/USD declining while DXY is forecast DOWN is counter-cascade. This rule applies a structural penalty to such paths.

**Threshold:** Binary gate. If the path direction is counter-cascade, a penalty of 0.15 is subtracted from the combined structural score. If aligned, no penalty. The 0.15 penalty is calibrated so that a counter-cascade path can still achieve a passing score (0.5 or above) if zone respect, shape match, and knowledge graph are all excellent — but it cannot reach the top tier (0.85 or above) needed for grade-A recommendation.

**Threshold sensitivity:** At 0.14 (minus 0.01), a counter-cascade path with otherwise perfect structural scores (1.0 on all three sub-scores) would reach 0.86, barely entering grade-A territory. At 0.16 (plus 0.01), the same path would reach 0.84, just below grade-A. The 0.15 value sits exactly at the boundary — counter-cascade paths can never be grade-A regardless of other scores. This is the intended behavior: DXY cascade is a directional anchor, and contradicting it caps the path's quality.

**Edge case:** If the DXY forecast is NEUTRAL, no cascade conditioning is applied and the check returns aligned=true with zero penalty. This handles chop/transition regimes where DXY direction is genuinely unclear. Referenced in Test 7 (Section 7).

```typescript
  /**
   * Rule 4: DXY Cascade Consistency.
   *
   * Checks whether the path's implied direction aligns with the DXY forecast.
   * For FX pairs: DXY DOWN -> pair should be LONG biased.
   * Counter-cascade paths receive a 0.15 penalty.
   */
  private checkDxyCascade(ctx: DefenseContext): { check: DxyCascadeCheck; flags: DefenseFlag[] } {
    const flags: DefenseFlag[] = [];

    if (ctx.pair === 'DXY' || ctx.dxyForecast === TradeDirection.NEUTRAL) {
      return {
        check: {
          conditioned: false,
          dxyDirection: ctx.dxyForecast,
          pathDirection: TradeDirection.NEUTRAL,
          aligned: true, penalty: 0,
        },
        flags,
      };
    }

    const h4Candles = this.getLayerCandles(ctx.path, KronosTimeframe.H4);
    if (h4Candles.length < 2) {
      return {
        check: {
          conditioned: true,
          dxyDirection: ctx.dxyForecast,
          pathDirection: TradeDirection.NEUTRAL,
          aligned: true, penalty: 0,
        },
        flags,
      };
    }

    const firstClose = h4Candles[0]!.close;
    const lastClose = h4Candles[h4Candles.length - 1]!.close;
    const netMove = lastClose - firstClose;
    const directionThreshold = ctx.pipValue * CASCADE_DIRECTION_THRESHOLD_PIPS;

    let pathDirection: TradeDirection;
    if (netMove > directionThreshold) pathDirection = TradeDirection.LONG;
    else if (netMove < -directionThreshold) pathDirection = TradeDirection.SHORT;
    else pathDirection = TradeDirection.NEUTRAL;

    const expectedFxDirection = ctx.dxyForecast === TradeDirection.SHORT
      ? TradeDirection.LONG
      : ctx.dxyForecast === TradeDirection.LONG
        ? TradeDirection.SHORT
        : TradeDirection.NEUTRAL;

    const aligned = pathDirection === TradeDirection.NEUTRAL ||
                    expectedFxDirection === TradeDirection.NEUTRAL ||
                    pathDirection === expectedFxDirection;

    const penalty = aligned ? 0 : DXY_CASCADE_PENALTY;

    if (!aligned) {
      flags.push({
        ruleId: 4, ruleName: 'DXY Cascade', severity: 'WARN',
        message: `Path direction ${pathDirection} is counter-cascade (DXY ${ctx.dxyForecast} -> expected ${expectedFxDirection}). Penalty: ${penalty}`,
      });
    }

    return {
      check: { conditioned: true, dxyDirection: ctx.dxyForecast,
               pathDirection, aligned, penalty },
      flags,
    };
  }
```

**Constants:**

```typescript
const CASCADE_DIRECTION_THRESHOLD_PIPS = 15;
const DXY_CASCADE_PENALTY = 0.15;
```

## 5.5 Defense Rule 5 — Knowledge Graph Historical Match

**Purpose:** Check whether the path's pattern (pair + shape + zone type + direction) has occurred in the 43 winning trades. If similar patterns historically produced wins, the path gets a knowledge boost. If similar patterns historically produced losses, the path is penalized.

**Threshold:** The knowledge score is `winningMatches / (winningMatches + losingMatches)`. If no historical matches exist, the score defaults to 0.5 (neutral — the pattern is novel, neither rewarded nor penalized). A score of 0.7 or above triggers an INFO boost flag; a score below 0.3 triggers a WARN penalty flag. Referenced in Test 8 (Section 7).

**Edge case:** If the knowledge graph is empty (no historical data loaded), the score defaults to 0.5 and a flag is raised noting the absence of historical context. This prevents the engine from penalizing all paths equally when historical data is unavailable.

```typescript
  /**
   * Rule 5: Knowledge Graph Historical Match.
   *
   * Queries the historical trade intelligence graph for patterns matching
   * the path's characteristics (pair, shape, zone type, direction).
   * Returns a score based on the win/loss ratio of matching patterns.
   */
  private checkKnowledgeGraph(ctx: DefenseContext): { score: number; flags: DefenseFlag[] } {
    const flags: DefenseFlag[] = [];

    if (ctx.knowledgeGraph.length === 0) {
      flags.push({
        ruleId: 5, ruleName: 'Knowledge Graph', severity: 'INFO',
        message: 'Knowledge graph is empty — no historical match available',
      });
      return { score: 0.5, flags };
    }

    const pathShapes = this.getPathShapes(ctx.path);
    const pathDirection = this.getPathDirection(ctx.path, ctx.pipValue);
    const pathZoneTypes = this.getPathZoneTypes(ctx.path, ctx.zoneMap);

    let winningMatches = 0;
    let losingMatches = 0;
    const matchedNodes: KnowledgeNode[] = [];

    for (const node of ctx.knowledgeGraph) {
      if (node.pair !== ctx.pair) continue;
      if (!pathShapes.includes(node.shapeCode)) continue;
      if (node.direction !== pathDirection && node.direction !== TradeDirection.NEUTRAL) continue;
      if (!pathZoneTypes.includes(node.zoneType)) continue;

      matchedNodes.push(node);
      if (node.outcome === 'WIN') winningMatches++;
      else losingMatches++;
    }

    if (matchedNodes.length === 0) {
      return { score: 0.5, flags };
    }

    const score = winningMatches / (winningMatches + losingMatches);

    if (score >= KNOWLEDGE_MATCH_BOOST_THRESHOLD) {
      flags.push({
        ruleId: 5, ruleName: 'Knowledge Graph', severity: 'INFO',
        message: `${winningMatches}/${matchedNodes.length} historical matches were WINS (score=${score.toFixed(2)})`,
      });
    } else if (score < KNOWLEDGE_MATCH_PENALTY_THRESHOLD) {
      flags.push({
        ruleId: 5, ruleName: 'Knowledge Graph', severity: 'WARN',
        message: `${losingMatches}/${matchedNodes.length} historical matches were LOSSES (score=${score.toFixed(2)})`,
      });
    }

    return { score, flags };
  }

  private getPathShapes(path: FractalPath): ShapeCode[] {
    const h1Candles = this.getLayerCandles(path, KronosTimeframe.H1);
    const dayGroups = this.groupCandlesByDay(h1Candles);
    const shapes: ShapeCode[] = [];
    for (const [, dayCandles] of dayGroups) {
      const avgBody = dayCandles.reduce((s, c) => s + c.bodyFraction, 0) / dayCandles.length;
      if (avgBody > 0.5) shapes.push(ShapeCode.BS);
      else if (avgBody < 0.3) shapes.push(ShapeCode.SS);
      else shapes.push(ShapeCode.WL);
    }
    return shapes;
  }

  private getPathDirection(path: FractalPath, pipValue: number): TradeDirection {
    const h4Candles = this.getLayerCandles(path, KronosTimeframe.H4);
    if (h4Candles.length < 2) return TradeDirection.NEUTRAL;
    const first = h4Candles[0]!.close;
    const last = h4Candles[h4Candles.length - 1]!.close;
    const net = last - first;
    const threshold = pipValue * CASCADE_DIRECTION_THRESHOLD_PIPS;
    if (net > threshold) return TradeDirection.LONG;
    if (net < -threshold) return TradeDirection.SHORT;
    return TradeDirection.NEUTRAL;
  }

  private getPathZoneTypes(path: FractalPath, zoneMap: ZoneMapSnapshot): ZoneType[] {
    const candles = this.getLayerCandles(path, KronosTimeframe.H1);
    const touched = new Set<ZoneType>();
    for (const candle of candles) {
      for (const zone of zoneMap.zones) {
        if (candle.low <= zone.ceiling && candle.high >= zone.floor) {
          touched.add(zone.type);
        }
      }
    }
    return Array.from(touched);
  }
```

**Constants:**

```typescript

const KNOWLEDGE_MATCH_PENALTY_THRESHOLD = 0.3;
```

## 5.6 Defense Rule 6 — OHLCV Sanity

**Purpose:** Reject paths whose forecasted candles violate basic price constraints. The Kronos model, like all generative models, can produce physically impossible candles: high below open, low above close, negative volume, NaN values. These are model artifacts, not market predictions. They must be caught before the path enters the scoring pipeline.

**Threshold:** Hard reject. Any path with even one candle failing the sanity check is rejected entirely. There is no partial sanity — a path is either entirely valid or it is garbage.

**Edge case:** A candle with high equal to open equal to close equal to low (a doji with zero range) is technically valid but degenerate. Such candles are accepted but would receive density 0 in practice. The OHLCV epsilon tolerance of 0.000005 (0.5 pips) allows for float rounding noise without accepting real violations. Referenced in Test 11 (Section 7).

```typescript
  /**
   * Rule 6: OHLCV Sanity Check.
   *
   * Validates that every candle in every layer satisfies basic constraints:
   *   - high >= max(open, close)
   *   - low <= min(open, close)
   *   - volume >= 0
   *   - all values finite (no NaN, no Infinity)
   *
   * @returns { passed: boolean, reason: string }
   */
  private checkOhlcvSanity(path: FractalPath): { passed: boolean; reason: string } {
    for (const layer of path.layers) {
      for (let i = 0; i < layer.candles.length; i++) {
        const candle = layer.candles[i];
        if (!candle) {
          return { passed: false, reason: `${layer.timeframe}[${i}]: candle is undefined` };
        }

        const values = [candle.open, candle.high, candle.low, candle.close, candle.volume];
        for (const v of values) {
          if (!Number.isFinite(v)) {
            return { passed: false,
              reason: `${layer.timeframe}[${i}]: non-finite value (open=${candle.open}, high=${candle.high}, low=${candle.low}, close=${candle.close}, vol=${candle.volume})` };
          }
        }

        const maxOC = Math.max(candle.open, candle.close);
        if (candle.high < maxOC - OHLCV_EPSILON) {
          return { passed: false,
            reason: `${layer.timeframe}[${i}]: high (${candle.high}) < max(open,close) (${maxOC})` };
        }

        const minOC = Math.min(candle.open, candle.close);
        if (candle.low > minOC + OHLCV_EPSILON) {
          return { passed: false,
            reason: `${layer.timeframe}[${i}]: low (${candle.low}) > min(open,close) (${minOC})` };
        }

        if (candle.volume < 0) {
          return { passed: false,
            reason: `${layer.timeframe}[${i}]: negative volume (${candle.volume})` };
        }
      }
    }
    return { passed: true, reason: '' };
  }
```

**Constants:**

```typescript

```

## 5.7 Defense Rule 7 — Temporal Consistency

**Purpose:** Verify that all candle timestamps are in ascending sequence and match the expected timeframe spacing. A path with timestamps out of order, or with M15 candles spaced 1 hour apart, has a corruption or parsing error.

**Threshold:** Hard reject. Any timestamp inconsistency rejects the entire path. The tolerance for spacing deviation is 5% of the expected timeframe duration — for M15 (900,000 ms), that is 45,000 ms (45 seconds). This allows for minor clock drift between the model server and the pipeline without accepting real temporal corruption.

**Edge case:** The first candle's timestamp is allowed to be the context end time (not strictly greater than the last context candle), since it represents the start of the forecast window. Referenced in Test 1 (Section 7, which verifies the temporal structure is correct for valid paths).

```typescript
  /**
   * Rule 7: Temporal Consistency Check.
   *
   * Verifies candle timestamps are ascending and match timeframe spacing.
   *
   * @returns { passed: boolean, flags }
   */
  private checkTemporalConsistency(ctx: DefenseContext): { passed: boolean; flags: DefenseFlag[] } {
    const flags: DefenseFlag[] = [];

    for (const layer of ctx.path.layers) {
      const expectedSpacing = TIMEFRAME_MS[layer.timeframe];
      const tolerance = expectedSpacing * TEMPORAL_TOLERANCE_RATIO;

      for (let i = 1; i < layer.candles.length; i++) {
        const prev = layer.candles[i - 1];
        const curr = layer.candles[i];
        if (!prev || !curr) continue;

        if (curr.timestamp <= prev.timestamp) {
          flags.push({
            ruleId: 7, ruleName: 'Temporal Consistency', severity: 'BLOCK',
            message: `${layer.timeframe}[${i}]: timestamp ${curr.timestamp} <= previous ${prev.timestamp}`,
          });
          return { passed: false, flags };
        }

        const actualSpacing = curr.timestamp - prev.timestamp;
        const deviation = Math.abs(actualSpacing - expectedSpacing);
        if (deviation > tolerance) {
          flags.push({
            ruleId: 7, ruleName: 'Temporal Consistency', severity: 'BLOCK',
            message: `${layer.timeframe}[${i}]: spacing ${actualSpacing}ms deviates from expected ${expectedSpacing}ms by ${deviation}ms`,
          });
          return { passed: false, flags };
        }
      }
    }
    return { passed: true, flags };
  }
```

**Constants:**

```typescript
const TEMPORAL_TOLERANCE_RATIO = 0.05;
```

## 6A. Telescoping Algorithm

### Purpose

The telescoping algorithm converts a coarse-timeframe forecast (H4) into fine-timeframe forecasts (H1, M30, M15) by establishing range anchors. Each parent candle's high and low become hard bounds for all child candles within the parent's time window. This ensures that the fine-timeframe forecast is geometrically consistent with the coarse-timeframe forecast — a child candle can never exceed the parent's range.

### Formula

Given an H4 candle P with open O_p, high H_p, low L_p, close C_p, covering time window [t_start, t_end):

The set of H1 range anchors derived from P:

```
For each H1 candle C_i within [t_start, t_end):
    C_i.high  <= H_p    (ceiling constraint)
    C_i.low   >= L_p    (floor constraint)
```

The number of H1 candles per H4 window:

```
N_H1 = (t_end - t_start) / H1_duration = 4h / 1h = 4
```

Each H1 bar is then clamped:

```
C_i.high  = min(raw_high_i,  H_p)
C_i.low   = max(raw_low_i,   L_p)
C_i.open  = clamp(raw_open_i,  L_p, H_p)
C_i.close = clamp(raw_close_i, L_p, H_p)
```

### Complexity

```
O(N * M) where:
  N = context candles fed to the model (30 for H4)
  M = forecast candles per layer

Clamping per layer is O(M). Total across 4 layers:
  O(N * M_H1 + M_H1 * M_M30 + M_M30 * M_M15)
```

## 6B. First-Passage Algorithm

### Purpose

Given a sequence of OHLCV candles and a trade specification (entry, SL, TP, direction), determine the probability that TP is reached before SL. This is the classic first-passage problem from stochastic processes, applied to discrete candle paths rather than continuous diffusion.

### Formula

For a set of P paths, each containing N candles:

```
P(entry triggered) = count(paths where entry level is touched) / P

P(TP before SL | entry triggered) =
    count(paths where TP touched before SL, after entry) /
    count(paths where entry touched)

P(SL before TP | entry triggered) =
    count(paths where SL touched before TP, after entry) /
    count(paths where entry touched)
```

**Entry trigger conditions:**

```
LONG:  entry triggered when candle.low <= entry
SHORT: entry triggered when candle.high >= entry
```

**TP/SL touch conditions (after entry):**

```
LONG:  TP touched when candle.high >= tp | SL touched when candle.low <= sl
SHORT: TP touched when candle.low <= tp  | SL touched when candle.high >= sl
```

**Same-candle resolution:** If both TP and SL are touched within the same candle, the closer level wins:

```
LONG:  if (high - tp) <= (sl - low) -> TP first, else SL first
SHORT: if (tp - low) <= (high - sl) -> TP first, else SL first
```

**Expected value:**

```
EV_pips = P(TP first) * |tp - entry| / pip_value  -  P(SL first) * |entry - sl| / pip_value
```

### Complexity

```
O(N * P) where:
  N = candles per path (M15 layer: ~48 candles for 12-hour forecast)
  P = number of paths (15 per pair, 75 for GBP/USD)

Total per setup: 48 * 15 = 720 iterations (or 48 * 75 = 3600 for GBP/USD)
```

Sub-millisecond in TypeScript.

## 6C. Structural Scoring Algorithm

### Purpose

Combine three independent structural sub-scores (zone respect, shape morphology, knowledge graph) into a single structural confidence value. The combination uses fixed weights derived from empirical analysis of the 43 winning trades.

### Formula

```
structuralScore = w_zone * zoneScore + w_shape * shapeScore + w_knowledge * knowledgeScore

where:
  w_zone      = 0.40
  w_shape     = 0.30
  w_knowledge = 0.30
  (weights sum to 1.0)

Then:
  structuralScore *= fortressMultiplier   (0.5 if violated, 1.0 if clean)
  structuralScore -= dxyCascadePenalty     (0.15 if counter-cascade, 0 if aligned)
  structuralScore  = clamp(structuralScore, 0, 1)
```

### Weight Rationale

- **Zone (0.40):** Zone architecture is the most reliable structural signal. The core TTE premise — "price sweeps liquidity zone by zone in sequential order" — means zone edges are the primary determinants of price behavior. Zone respect gets the highest weight.

- **Shape (0.30):** Shape predictions from Engine 2 are useful but less reliable than zone data. Shapes can transition unexpectedly (SS to BS when consolidation breaks early). Shape gets a moderate weight.

- **Knowledge (0.30):** Historical pattern matching is valuable but limited by sample size (43 trades is small). Knowledge gets the same weight as shape because novel patterns (no historical match) receive a neutral 0.5, so the knowledge score only affects paths that DO have matches.

### Complexity

```
O(Z * P + S * P + K * P) where:
  Z = zones per pair (typically 5)
  S = shape codes per day (1-2)
  K = knowledge graph nodes (43)
  P = paths (15)

Total: (5 + 2 + 43) * 15 = 750 iterations per pair
```

## 6D. Previous Week Terminal Shape Classification

### Purpose

Classify what shape actually played out from the prior week's OHLCV data. This terminal shape becomes the energy level and starting condition for the current week's shape chain. A week that ended with a Breakout Surge enters the new week with high directional energy. A week that ended with Swing Scalps enters with depleted energy and consolidation expectations.

### Algorithm

```python
def classify_terminal_shape(ohlcv_week: list[dict]) -> dict:
    """
    Classify the prior week's terminal shape from H4 OHLCV data.

    Uses zone interaction analysis (same logic as Engine 2 shape-brain
    but applied to historical/completed data rather than forecast).

    Args:
        ohlcv_week: List of H4 OHLCV dicts for the completed prior week.
                    Each dict has keys: timestamp, open, high, low, close, volume.
                    Typically ~30 bars (Mon-Fri, 6 bars/day).

    Returns:
        dict with keys: terminal_shape, confidence, expected_start_shape,
                        energy_level, ended_at_extreme, evidence[]
    """
    if len(ohlcv_week) < 10:
        return {
            "terminal_shape": "SS",
            "confidence": 0.3,
            "expected_start_shape": "SS",
            "energy_level": "DECLINING",
            "ended_at_extreme": False,
            "evidence": ["Insufficient data for classification"],
        }

    # Compute weekly statistics
    highs = [bar["high"] for bar in ohlcv_week]
    lows = [bar["low"] for bar in ohlcv_week]
    opens = [bar["open"] for bar in ohlcv_week]
    closes = [bar["close"] for bar in ohlcv_week]

    weekly_high = max(highs)
    weekly_low = min(lows)
    weekly_range = weekly_high - weekly_low
    first_open = opens[0]
    last_close = closes[-1]

    # Body fraction per candle
    body_fractions = []
    for o, h, l, c in zip(opens, highs, lows, closes):
        candle_range = h - l
        if candle_range > 0:
            body_fractions.append(abs(c - o) / candle_range)
        else:
            body_fractions.append(0.0)

    avg_body = sum(body_fractions) / len(body_fractions)

    # Directional consistency: fraction of candles with same sign as net move
    net_move = last_close - first_open
    net_sign = 1 if net_move > 0 else (-1 if net_move < 0 else 0)
    directional_count = sum(
        1 for o, c in zip(opens, closes)
        if (1 if c > o else (-1 if c < o else 0)) == net_sign
    )
    directional_consistency = directional_count / len(opens)

    # Max single-bar range vs average
    bar_ranges = [h - l for h, l in zip(highs, lows)]
    avg_bar_range = sum(bar_ranges) / len(bar_ranges)
    max_bar_range = max(bar_ranges) if bar_ranges else 0

    # End vs start position
    if weekly_range > 0:
        end_vs_start = (last_close - first_open) / weekly_range
    else:
        end_vs_start = 0.0

    evidence = []
    evidence.append(f"avg_body_fraction={avg_body:.3f}")
    evidence.append(f"directional_consistency={directional_consistency:.3f}")
    evidence.append(f"end_vs_start={end_vs_start:.3f}")

    # Classification decision tree
    if avg_body > 0.50 and abs(end_vs_start) > 0.40:
        shape = "BS"
        energy = "PEAK"
        expected_start = "RWL"
        confidence = 0.85
        evidence.append("Large bodies + directional close -> Breakout Surge")
    elif avg_body < 0.25 and directional_consistency < 0.30:
        shape = "SS"
        energy = "DECLINING"
        expected_start = "SS"
        confidence = 0.80
        evidence.append("Small bodies + low consistency -> Swing Scalps (consolidation)")
    elif max_bar_range > 2 * avg_bar_range and 0.20 <= avg_body <= 0.50:
        shape = "WL"
        energy = "EXHAUSTED"
        expected_start = "RWL"
        confidence = 0.75
        evidence.append("Wide single-bar range + moderate body -> Whiplash")
    elif end_vs_start > 0.50 and avg_body > 0.35:
        shape = "R"
        energy = "RISING"
        expected_start = "BS"
        confidence = 0.70
        evidence.append("Strong directional move -> Reversal")
    else:
        shape = "SS"
        energy = "DECLINING"
        expected_start = "SS"
        confidence = 0.50
        evidence.append("Default classification -> Swing Scalps")

    ended_at_extreme = (
        last_close >= weekly_high - weekly_range * 0.05 or
        last_close <= weekly_low + weekly_range * 0.05
    )

    return {
        "terminal_shape": shape,
        "confidence": confidence,
        "expected_start_shape": expected_start,
        "energy_level": energy,
        "ended_at_extreme": ended_at_extreme,
        "evidence": evidence,
    }
```

### Complexity

```
O(N) where N = number of H4 bars in the prior week (~30).
Single pass through the candle array. Negligible compute.
```

This section documents what KronosCandleEngine cannot predict, why it cannot, and what fallback mechanism catches the gap. Every blind spot has a corresponding defense rule or fallback that prevents it from producing silently wrong results.

## 8.1 Blind Spot: Mean-Reversion Bias in Kronos Model

Kronos was trained on equities and crypto data, not FX. Equity and crypto markets exhibit stronger mean-reversion tendencies than FX, especially during trending regimes. This means Kronos may generate paths that revert to the mean too aggressively — forecasting a bounce when the actual market is in a clean directional trend. On EUR/USD during a strong DXY-driven downtrend, Kronos might predict a mean-reversion bounce that never materializes.

**Fallback:** The TTE structural direction (DXY cascade, Defense Rule 4) overrides Kronos direction. If DXY is forecast SHORT and the structural zone architecture supports EUR/USD LONG, but Kronos generates a SHORT-biased path (mean-reverting from a local high), the DXY cascade check flags the path as counter-cascade and applies the 0.15 structural penalty. This ensures the TTE directional thesis dominates the model's mean-reversion artifact. The 70/30 split further dilutes the model's directional influence — even a completely wrong Kronos direction can only contribute 30% to the final path probability, and the structural penalty reduces that further.

## 8.2 Blind Spot: Kronos Cannot See Zones

Kronos generates paths from candlestick patterns alone. It does not receive zone data as input — it does not know where demand floors or supply ceilings are. It can generate a path that slices through three demand zones without bouncing, because the model has no concept of zones. It sees only price and volume sequences.

**Fallback:** The zone projection scoring (Defense Rule 1) catches paths that violate zone architecture. Every path is checked against the Engine 1 zone map. A path that ignores zone edges receives a low zoneScore (potentially 0), which dominates the structural score due to the 0.40 weight. Even if the model is highly confident in the path (modelConfidence = 0.9), the 70% structural weight means the zone-violating path receives at most 0.30 * 0.9 + 0.70 * 0 = 0.27 pathProbability — well below the 0.5 threshold for meaningful recommendation.

## 8.3 Blind Spot: OHLCV Consistency Not Guaranteed

The Kronos model is a generative neural network. Like all generative models, it can produce outputs that violate basic physical constraints. A forecasted candle might have high below open, low above close, or negative volume. These are model artifacts, not market predictions. Without a sanity check, such candles would propagate into the first-passage algorithm and produce nonsensical probability estimates.

**Fallback:** The OHLCV sanity check (Defense Rule 6) hard-rejects any path containing invalid candles. This is the one and only hard gate in KCE — all other defense rules are advisory (penalties, not rejections). A path with even one NaN or inverted candle is discarded before it enters the scoring pipeline. If ALL paths for a pair fail sanity (extremely rare), the engine falls back to advisory-only mode for that pair, returning neutral 0.5 probabilities that do not affect setup confidence.

## 8.4 Blind Spot: Session-Specific Volatility Patterns

Kronos may not capture the London open volatility spike (02:00-05:00 ET) or the NY overlap reversal pattern (08:00-10:00 ET). These session-specific dynamics are well-documented in the TTE methodology but may not be strongly represented in the model's training data. The model might forecast smooth price action through the London open when the real market exhibits a sharp 15-20 pip spike.

**Fallback:** The TTE session map provides expected volatility context. Engine 3 already assigns setups to specific session windows (London Open, NY Overlap, etc.). The M30 telescope layer receives the session hint as a conditioning input (`session_hint` parameter), which biases the model toward session-appropriate volatility. Additionally, the first-passage algorithm evaluates the M15 layer, which is the finest granularity and captures within-session wick behavior. If the model underestimates the London open spike, the SL wick risk is captured in the first-passage P(SL before TP) statistic.

## 8.5 Blind Spot: Multi-Timeframe Telescoping Information Loss

Converting H4 to H1 anchors loses information. The H4 candle is a compressed representation of 4 hours of price action. When we decompress it into H1 candles, we recover the intra-window shape, but the exact path within the window (which hour had the high, which had the low) is an inference, not a fact. The clamping operation (limiting H1 highs to H4 ceiling) is geometrically correct but temporally lossy.

**Fallback:** The structural score downweights paths where the H1 forecast diverges significantly from the H4 anchors. If the model's raw H1 output requires heavy clamping (multiple candles clamped by more than 5 pips), this indicates the model disagrees with the H4 structure. The clamped candles have artificially compressed ranges, which reduces their bodyFraction, which in turn lowers the shape morphology score. This creates a feedback mechanism: telescoping inconsistency is penalized through the shape morphology check without requiring an explicit divergence metric.

## 8.6 Blind Spot: Model Drift Over Time

Kronos accuracy may degrade as market regimes change. The model was trained on historical data. If the current market regime (e.g., a new central bank policy cycle, a geopolitical shock) differs significantly from the training period, the model's candlestick patterns may no longer be predictive. Model drift is gradual and difficult to detect in real-time.

**Fallback:** The calibration tracker monitors KCE accuracy week over week. Each week, the predicted first-passage probabilities are compared against actual outcomes (once trades are closed). If KCE's P(TP before SL) systematically diverges from the realized win rate by more than 15 percentage points over 4 consecutive weeks, the engine automatically reduces the modelWeight from 0.30 to 0.15 (halving the model's influence) and increases the structuralWeight from 0.70 to 0.85. This adaptive weight adjustment ensures that a drifting model cannot corrupt the pipeline — the structural intelligence takes over when the model becomes unreliable.

## 8.7 Blind Spot: News Event Shocks

Kronos cannot predict news event shocks (NFP, FOMC, central bank decisions). These events cause instantaneous 30-50 pip moves that no candlestick pattern model can anticipate. A path that looks perfect until 08:30 ET on NFP Friday can be completely invalidated by the data release.

**Fallback:** The red folder check in Engine 3 already defers setups near high-impact news events. Setups within 30 minutes of a red folder event are either excluded or marked as conditional. KCE respects this: during red folder windows, KCE paths are flagged as low-confidence. The `pEntryTriggered` probability for setups during news windows is naturally lower because the model's M15 layer cannot anticipate the volatility spike, and the first-passage algorithm will show high P(neither) — neither TP nor SL reached because the path horizon doesn't extend past the news event with sufficient resolution. The engine explicitly checks the economic calendar and adds a `redFolderWindow` flag to PathValidationResult when a setup's entry window overlaps a high-impact event.

# SECTION 12: MIGRATION

## 12.1 Migration Strategy Overview

KCE is introduced in three phases. Each phase is independently deployable and independently rollback-able. The pipeline continues to function correctly at every phase — KCE is always advisory, never blocking.

```
Phase 1 (Observe-Only) ──▶ Phase 2 (Advisory) ──▶ Phase 3 (Full Integration)
     KCE runs but            KCE scores feed       Per-pair instances,
     outputs logged,         into confluence       telescoping, knowledge
     not scored              bucket                 graph, calibration
```

## 12.2 Phase 1: Observe-Only

**What changes:**
- The KronosCandleEngine is instantiated and initialized (4 Python servers start on ports 7091-7094).
- Step 7.6 runs: fractal paths are generated, scored structurally, and first-passage is computed for each setup.
- All KCE output is written to a log file (`logs/kce-observe-{date}.json`) but does NOT modify any setup's confidence.
- The `confidenceDelta` from KCE is computed but deliberately set to 0 in the output (overridden).
- The report does NOT show KCE columns yet.

**What could break:**
- Python server startup failure: If the Kronos model fails to load (missing CUDA, wrong model ID, VRAM exhaustion), the `initialize()` method returns false and the engine enters structural-only mode. No crash, no data loss — the pipeline continues with the existing TimesFM-only path.
- Port conflicts: If ports 7091-7094 are already in use (unlikely in the container environment), the `startInstance` method fails and returns null. The engine logs a warning and runs structural-only.
- Performance regression: The KCE pass adds approximately 90 seconds to pipeline runtime. If the GPU is shared with TimesFM, there may be contention. Monitor GPU utilization during the first run.

**Rollback:**
1. Set the environment variable `PLUTUS_KCE_ENABLED=false`. This causes the pipeline to skip Step 7.6 entirely.
2. Alternatively, comment out the Step 7.6 code block in `plutus-tte-pipeline.ts` (lines after 1117). The pipeline reverts to the v3.3 behavior with no code changes needed elsewhere.
3. Kill any running Python Kronos servers: `pkill -f "kronos.server"`.

## 12.3 Phase 2: Advisory

**What changes:**
- KCE `confidenceDelta` is applied to setup confidence at Step 7.7 (no longer overridden to 0).
- Setups with KCE grade A receive +15 confidence; grade B receives +8; grade C receives 0; grade D receives -8; grade F receives -15.
- No setup is ever removed — the advisory-only design guarantees the setup count is unchanged.
- The report gains KCE columns (Grade, P(TP), P(SL), Structural Score, Recommend).
- The calibration tracker begins recording predicted vs realized win rates.

**What could break:**
- Confidence inflation: If KCE systematically over-grades (assigning A to setups that then lose), the confidence scores become unreliable. The calibration tracker detects this: if divergence exceeds 15 percentage points over 4 consecutive weeks, the model weight is automatically halved.
- Report formatting: The new columns may break the existing report layout if the column widths are not properly adjusted. Test the report generator with KCE data before deploying.
- Firewall interaction: KCE confidence adjustments may push a borderline setup above or below a confidence threshold that the semantic firewall uses. This is acceptable (the firewall re-evaluates after Step 7.7), but monitor for unexpected firewall rejections.

**Rollback:**
1. Set `PLUTUS_KCE_PHASE=1` (revert to observe-only). The confidence delta is overridden to 0 again.
2. Alternatively, set `PLUTUS_KCE_ENABLED=false` (disable entirely, reverting to v3.3 behavior).
3. The report generator conditionally renders KCE columns based on the phase flag, so rolling back to Phase 1 automatically hides the columns.

## 12.4 Phase 3: Full Integration

**What changes:**
- All 4 per-pair instances are active and running on dedicated GPU resources.
- The DXY-first ordering is enforced: DXY processes first, its directional forecast cascades to all FX pairs.
- The knowledge graph is fully loaded and queried by Defense Rule 5 for every path.
- The telescoping architecture runs all 4 layers (H4 to H1 to M30 to M15) with anchor clamping.
- Adaptive path count is active: GBP/USD generates 75 paths instead of 15.
- The calibration tracker is active and can automatically adjust model/structural weights.
- Previous week terminal shape classification feeds into Engine 2's shape chain prediction.

**What could break:**
- GPU VRAM exhaustion: 4 instances at 680 MB each = 2.72 GB. If the GPU has less than 3 GB free (after TimesFM and other processes), the last instance may fail to start. Monitor VRAM with `nvidia-smi`. If needed, reduce `vramBudgetPerInstanceMB` to 500 (still sufficient for the 200M parameter model).
- Scaling cliff: 4 pairs times 75 paths times 4 layers = 1200 model calls for GBP/USD alone. At 0.5s each, that is 600s (10 minutes) for GBP/USD. This is the adversarial scaling concern. Mitigation: paths are generated in parallel within the Python server (batch inference). The actual wall-clock time is approximately 90 seconds because the model processes batches of paths simultaneously, not sequentially.
- Knowledge graph staleness: The 43 trades in the knowledge graph may become outdated as market regimes shift. The calibration tracker does not directly address knowledge graph staleness. Mitigation: manually update the knowledge graph quarterly with new trade outcomes from the Handover_Data.

**Rollback:**
1. Set `PLUTUS_KCE_PHASE=2` (revert to advisory without full integration features).
2. Set `PLUTUS_KCE_PHASE=1` (revert to observe-only).
3. Set `PLUTUS_KCE_ENABLED=false` (disable KCE entirely — reverts to v3.3 behavior).
4. Kill Python servers: `pkill -f "kronos.server"`.
5. Revert the pipeline code to the pre-KCE checkpoint: `git checkout v3.3 -- src/engine/plutus-tte-pipeline.ts`.

# ADVERSARIAL CHALLENGES

## Challenge 1: FALSE_POSITIVE — Kronos Noise Masquerading as Breakout

**Scenario:** Kronos generates a path that looks like a Breakout Surge (expanding candles, directional closes, increasing volume) but is actually just model noise from its mean-reversion bias. The model sees a local high and generates an "expansion" that is really just the model struggling with a trending regime.

**How the structural score catches this:**

The zone respect check (Defense Rule 1) is the primary catcher. A genuine breakout corresponds to a zone ceiling breach — price breaks through a supply zone and continues. If the path's "breakout" does not correspond to an actual zone ceiling breach, it is a false positive. Specifically: if the expanding candles occur in the middle of a range with no zone interaction, the zoneScore defaults to 0.5 (neutral — no touches to evaluate). This neutral score, combined with the 0.40 weight, keeps the structural score moderate rather than high.

The shape morphology check (Defense Rule 3) is the secondary catcher. If the expanding candles do not align with the predicted shape chain day, they are downweighted. For example, if Engine 2 predicts SS (Swing Scalps) for Tuesday but Kronos generates BS-like expanding candles, the shape match score drops because the morphology does not match SS criteria (body fraction above 0.50 when SS expects below 0.35). The mismatch is flagged and the shapeScore decreases.

The combination ensures: a false-positive breakout that does not correspond to zone architecture AND does not match the predicted shape receives a structural score below 0.5, which caps the path probability below 0.5 — insufficient for a grade-A or grade-B recommendation.

## Challenge 2: THRESHOLD_CALIBRATION — Path Count for Volatile Pairs

**Scenario:** The default 15-path threshold may be too few for high-volatility pairs like GBP/USD, which has ATR approximately 1.5 times that of EUR/USD. With only 15 paths, the first-passage probability estimates have high variance — the confidence interval on P(TP before SL) is roughly plus or minus 0.13 with 15 paths.

**Solution — Adaptive Path Count:**

KCE implements adaptive path count based on pair volatility. The configuration property `highVolatilityPathBoost` (default 75) is applied to GBP/USD specifically. Pairs with ATR above 2 times the normal ATR for their category receive the boosted path count.

```typescript
const adaptivePaths = pair === 'GBP/USD'
  ? Math.max(basePaths, this.config.highVolatilityPathBoost)  // 75
  : basePaths;  // 15
```

With 75 paths, the confidence interval on P(TP before SL) shrinks to approximately plus or minus 0.06 — a meaningful improvement in estimate precision. The calibration tracker monitors convergence: if the win rate estimate changes by more than 5 percentage points when path count is doubled, it flags the pair as "path-starved" and recommends further increasing the count.

The scaling concern (75 paths times 4 layers = 300 calls per pair) is addressed by batch inference in the Python server. The model processes all 75 paths in a single forward pass (batched), reducing wall-clock time to approximately 2-3 seconds per pair rather than 37 seconds (75 times 0.5s sequential).

## Challenge 3: SCALING — 240 predict() Calls

**Scenario:** With 4 pairs, 15 fractal paths (75 for GBP/USD), and 4 telescope layers, the total number of model inference calls is: 3 pairs times 15 paths times 4 layers + 1 pair times 75 paths times 4 layers = 180 + 300 = 480 calls. At 0.5 seconds each sequentially, that is 240 seconds — 4 minutes.

**Solution — Parallel Architecture:**

The calls are NOT sequential. They follow two levels of parallelism:

1. **Inter-pair parallelism:** The 4 pairs run on separate GPU instances (ports 7091-7094). Each instance has its own model loaded in VRAM. The 4 instances process simultaneously, so the wall-clock time for inter-pair parallelism is max(individual pair times), not sum.

2. **Intra-pair batch parallelism:** Within each pair, the 15 (or 75) paths are generated in a single batched forward pass. The Kronos model supports batch inference — all paths for a pair are generated in one call, not 15 separate calls. The telescope layers are sequential (H4 conditions H1, etc.), but within each layer, all paths are batched.

**Actual wall-clock breakdown:**

```
Per pair:
  Layer 1 (H4): 1 batched call for all paths = ~0.5s
  Layer 2 (H1): 1 batched call = ~0.5s
  Layer 3 (M30): 1 batched call = ~0.5s
  Layer 4 (M15): 1 batched call = ~0.5s
  Total per pair: ~2.0s (model inference only)

Across 4 pairs (parallel):
  Total model inference: ~2.0s (max of 4 parallel instances)

Plus structural scoring (TypeScript, parallel):
  ~5s per pair (750 iterations)

Plus first-passage (TypeScript):
  ~1s per setup, ~10s per pair

Total wall-clock: ~20-90s depending on setup count
```

The 90-second estimate in the Executive Summary accounts for server startup (3s health check per instance), model warmup, and Python-to-TypeScript HTTP overhead. There is no scaling cliff — the architecture is designed for O(1) wall-clock scaling with path count (batched) and O(1) wall-clock scaling with pair count (parallel instances).

## Challenge 4: INTERACTION — Zone Respect vs Shape Morphology Conflict

**Scenario:** A path that respects zones (bounces at demand floor, rejects at supply ceiling) might not match the predicted shape. Engine 2 predicts BS (Breakout Surge) for Monday, but the path shows price bouncing at a demand zone and staying in range — which looks like SS (Swing Scalps), not BS. Which check wins?

**Resolution — Zone Wins by Design:**

Zone respect has weight 0.40, shape match has weight 0.30. Zone wins by design. The rationale: zone architecture is a structural fact (the zones exist, their edges are known price levels), while shape prediction is a forecast (Engine 2's shape chain can be wrong). When they conflict, the structural fact takes precedence over the forecast.

**Worked example:** A path receives zoneScore = 0.9 (excellent zone respect — bounces at D2, rejects at R2) but shapeScore = 0.3 (candles look like SS, not the predicted BS). The combined raw score is:

```
rawCombined = 0.40 * 0.9 + 0.30 * 0.3 + 0.30 * knowledgeScore
```

Even if knowledgeScore = 0.5 (neutral):

```
rawCombined = 0.36 + 0.09 + 0.15 = 0.60
```

This is above the 0.5 threshold — the path is not rejected despite the shape mismatch. The zone respect pulled it through. But the path will NOT receive a grade-A recommendation (which requires a combined score above 0.85). The shape mismatch caps it at grade B or C.

The zone-wins-by-design principle also manifests in the defense flags: a zone respect WARN flag (path didn't bounce at a zone) is more impactful than a shape morphology WARN flag, because the zone score has higher weight. Operators reviewing the report should prioritize fixing zone-related issues over shape-related issues.

## Challenge 5: BLIND_SPOT — News Event Shocks

**Scenario:** Kronos cannot predict NFP, FOMC, or central bank decision shocks. A path that looks perfect through Thursday can be completely invalidated by an 08:30 ET Friday NFP release that moves EUR/USD 40 pips in 30 seconds.

**Acknowledgment and Fallback:**

This blind spot is acknowledged and cannot be fully resolved by any candlestick forecasting model. The fallback is multi-layered:

1. **Red folder check (Engine 3):** Setups within 30 minutes of a high-impact news event are already deferred or marked conditional by Engine 3's economic calendar integration (`economic-calendar-client.ts`). This prevents KCE from evaluating setups that will be invalidated by news.

2. **KCE red folder flag:** KCE explicitly checks the economic calendar. If a setup's entry window overlaps a red folder event, the PathValidationResult includes a `redFolderWindow: true` flag. The report displays this as a warning icon next to the KCE grade.

3. **First-passage P(neither):** During news windows, the M15 layer's candle sequence cannot anticipate the volatility spike. The first-passage algorithm will show high P(neither) — neither TP nor SL reached within the path horizon, because the model's M15 candles don't extend far enough past the news event with sufficient volatility. This naturally reduces the path's quality grade.

4. **Operator override:** The report explicitly states: "KCE paths during red folder windows are flagged as low-confidence. Exercise manual judgment for trades near high-impact news events."

The combination of Engine 3 deferral, KCE flagging, first-passage P(neither) reduction, and explicit operator warning ensures that news event shocks do not silently corrupt the KCE output. The operator always knows when a KCE evaluation overlaps a red folder window.
